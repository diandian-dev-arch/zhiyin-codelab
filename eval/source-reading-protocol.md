# AI 项目解读：结果统计与语义评测协议

状态：统计工具已实现，代表项目及人工语义评测尚未完成。此协议补充项目解读优化方案，不替代课程实训既有四组评测协议。

## 1. 固定评测范围

开始前冻结样本 ZIP、应用构建和脱敏模型配置的 SHA-256，明确 quick/deep、生成开关、重复次数及预算。不同构建、模型配置、模式和离线／真实执行分开建立账本；对比时保留所有计划与失败样本。配置哈希不得包含密钥。

建议至少准备以下六类公开授权或专门编写的样本，每类保留正常和反例说明：

| 类别 | 必须核对的场景 | 反例／限制 |
| --- | --- | --- |
| 前端项目 | 页面操作到状态变化 | UI 文案不等于后端真实实现 |
| 后端服务 | 路由、校验、服务调用 | 被遮蔽的同名函数不能误连 |
| 全栈项目 | 页面、接口与存储的衔接 | 跨文件缺证据不得补造确定关系 |
| 脚本项目 | 输入、计算、输出 | 非 JS/TS 关系不能套用现有静态证明 |
| 缺文档／不完整项目 | 已有实现与未知环节 | 不以缺文件推断功能绝不存在 |
| 大目录／遗漏源码 | 导入限制与覆盖范围 | 不把未导入内容当作已核查 |

上述六类是原有开发样本；2026-10-17 按阅读 V2 扩展为 12 个专门编写的开发样本，见 [source-reading-corpus.ts](source-reading-corpus.ts)。新增单仓多包、长名称与路径、多语言、无 README/少量证据、无问题和历史格式阅读预期。样本包含预期理解、禁止断言和供核对的源码范围；大目录样本包含 120 个模块、体积超限文件及非 UTF-8 文件。它们用于发现回归，不是独立冻结评测集，也不代表真实项目规模与质量。历史格式样本的源码和阅读预期不是已生成的历史报告；旧格式渲染另外通过浏览器夹具验证。仍需公开授权的代表项目及独立人工评阅；已有同文件函数测试不能替代这些工作。

执行 `pnpm exec tsx scripts/check-source-corpus.ts` 可在内存中生成固定时间戳 ZIP，通过真实导入器，输出实际 SHA-256、保留文件数与遗漏原因。工具不写数据库、不执行样本代码、不调用模型；不得将其中预先编写的期望当作 AI 实测结果。

## 2. 可运行的只读统计

从仓库根运行：

```powershell
pnpm exec tsx scripts/check-source-evaluation.ts eval/source-reading-accounting-fixture.json
```

附带 JSON 是纯统计测试数据，重复字母哈希为占位值，未运行模型，不可作为实测报告。工具只读取指定账本并输出统计，不连接数据库、不发请求、不改文件。

真实账本沿用相同结构：`planned` 固定每次试验及样本哈希；`observations` 每个试验只保留一个服务端任务的最新观察。刷新不追加一条；一次新付费重试是新试验，须保留之前失败。工具拒绝重复试验、重复任务 ID、样本变更和不匹配的报告状态。未被服务端接受的导入或鉴权失败应另行记录原因，不伪造任务 ID。

`report` 仅复制质量元数据；历史警告只填 `legacyWarningPresent` 布尔值，不复制正文。不要填写源码、API Key、完整请求／回复或个人信息；额外字段会被拒绝，错误输出不回显输入值。

## 3. 指标口径

- `accepted`：账本内已被服务端接受的唯一任务数。
- `missing`：计划试验数减去已观察试验数；不可被悄悄移除。
- `terminal`：accepted 减去排队／运行中任务，包含失败和主动停止。
- `completeRate`：完整报告数 / terminal；受限率单列。
- `readableRate`：完整、受限、历史未知的可读报告数之和 / terminal；必须与三类数量同时呈现，不能称完整率。
- 分母为零时返回 `null`，不是 0% 或 100%。
- `knownCostCny` 是已知费用小计；`unknownCostTasks` 非零时不能当总费用。完全未知填 null，已知零费用才填 0；不完整价格／用量回执填 `costComplete=false`。
- `evaluationComplete` 只表示全部计划已有终态记录，不表示模型优秀；`semanticQualityVerified` 固定为 false。

工具校验格式、计数和样本哈希声明之间的一致性，不验证哈希是否来自真实文件，也无法识别人工篡改的执行类别。真实验收须单独核对原文件、任务回执和费用依据，不能直接把账本输入声明当证据。

## 4. 人工语义评阅

每个样本由评阅者逐项记录“通过／不通过／证据不足”及源码路径行号：用途是否符合实现；场景关键步骤是否遗漏；引用是否支持该结论；调用／数据关系是否被真实证明；推断是否明确；阅读建议是否有用。编造引用、把共享文件当调用、错版源码、越权信息任一出现均阻断链路开放，不以平均分掩盖。

人工结果独立保存，不由上述统计工具自动生成。真实模型需用户确认预算后执行；师生试测至少五人需真实参与，不以自动化脚本冒充。记录模式、版本、费用、失败及受限原因，区分机器校验、人工语义评阅与可用性试测。

## 5. 阅读 V2 的开放门禁

使用 [source-reading-review-template.md](source-reading-review-template.md) 分别记录源码核查者和目标读者的独立评价。六维各 0–2 分，单份报告至少 9/12，硬错误必须为 0；分歧保留原评分和证据，不能只保存平均值。真实付费运行和人工评分目前均未完成，不填写模拟分数。

比较同一样本、模型、模式、构建的生成开关开/关结果，记录实际输入/输出 token、已知费用、未知用量、总时延和失败。总预算先确认；达到上限、未知计费或硬错误时停止后续付费试验，不自动重发。不能因为请求次数仍为四次，就宣称增强内容没有额外 token 或费用。
