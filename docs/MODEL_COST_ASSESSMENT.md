## 性价比判断与实现优先级

本项目样本的Flash单次API绝对金额较低，但没有用户愿付意愿或质量/节时对照，不能直接认定产品划算。按全未命中计算，两次样本输入费用均占约83%，应优先减少重复源码输入，不能只压缩最终报告字数。

1. 优先实现费用透明：入队前显示模型、计价日期、估算区间；运行中显示已知小计及未知调用；结束后保存价格版本、逐调用用量与费用范围。未知用量不当0；保留历史模型快照，不用新价格改写旧账目。
2. 补齐provider缓存命中/未命中usage与逐调用阶段账本。若拆分缺失，仅按未命中估算并显式标注；官方直连与代理价格不能混用。当前公开API没有暴露逐调用缓存拆分，前端不能凭空推算。
3. 引入用户单次人民币预算与下一轮准入检查。已发出请求的输出预留、未知请求和跨时段较高价格都要占预算；客户端取消不等于退款。没有供应商侧限额配合时，不宣称扣款硬封顶。
4. 优化输入：稳定公共前缀提升缓存机会；复核只带相关片段与必要证据。当前source-agent多阶段会重复携带excerpts，应通过同样本消融比较成本和引用/漏报质量后逐步裁剪。
5. 默认经济模式，深入分析可选重点目录；历史报告直接重开不调用模型。相同ZIP现有去重继续保留。跨修改版本的增量分析需按文件哈希、依赖影响、模型与提示版本安全失效，不能只凭“文件没改”复用全部结论。
6. 将用户收益作为门槛：报告引用是否有效、建议是否可执行、是否减少理解和复核时间。优先保留证据校验，避免单纯删去复核轮次换取便宜但不可靠的输出。

以上是成本分析和下一步产品建议。本轮未改业务计费、模型配置、分析流程或默认额度，也未发起付费测试。
