# 四组评测账本使用说明

工具已实现；真实教师评阅与外部模型质量评测尚未发生。空模板、合成测试和软件校验不能作为参赛效果数据。

## 入口

```powershell
# 当前真实样本登记和协议文件的准备检查，不发模型请求
pnpm evaluation:check eval/empty-ledger.json
# 收集实际记录后；文件路径以项目根为起点，用正斜杠
pnpm evaluation:check .data/evaluation/study-v1.json
# 使用另一份已登记并保留的样本清单
pnpm evaluation:check .data/evaluation/study-v2.json .data/evaluation/registry-v2.json
```

默认样本清单为 `eval/development-registry.json`，11 份团队构造样本均在开发分区。空账本 `eval/empty-ledger.json` 固定其实际 SHA-256；重建登记文件导致字节改变时，校验会拒绝旧哈希，应检查变更并另建账本，不静默替换旧快照。

每次通过检查后在 `.data/evaluation-audits/<UUID>/` 保存输入账本、样本清单的字节快照和 result.json，均为私有材料。命令只打印状态、文件数、计划/记录数和私有摘要路径；失败不打印教师、模型或原始路径内容。输入文件和已引用的原始材料仍由操作者保留，审核快照不复制全部证据。

结果 `no_observations` 表示没有观察，`incomplete_records` 表示计划仍缺记录，`records_validated` 仅表示已提供记录的结构与材料哈希校验成功。三者均不会把 `qualityEvaluationCompleted` 标成 true。没有记录时费用为 null，不以零成本冒充已测结果。

## 收集顺序

1. 课程负责人先确认授权、保留与展示范围，独立教师/助教确认要求和真值。未完成时继续限定团队样本。
2. 在正式操作前确定协议和计划：实验代号、样本登记哈希、教师代号、H/R/S/A、重复编号、comparisonBlock。计划项保留，不因结果差而删除；每组/样本/块/重复编号不能重复。空模板没有擅自指定教师或生成计划样本量。
3. 实际操作时记录开始/结束、既往接触、是否盲评和五段不重叠时间。终点是同等质量反馈发布。失败、中止和尚未开始都保留在计划分母。
4. 导出实际输入、模型请求/响应、教师修订、发布与独立评分材料，私有保存并计算文件 SHA-256。按 [完整字段契约](../packages/contracts/src/evaluation.ts) 填写账本。
5. 运行上述命令，修正记录错误但保留更正版本。只有独立评阅确认语义质量和实验条件可比后，才能另行计算成效；工具不自动给节时百分比或准确率。

## 字段与证据

| 字段 | 填写要求 |
| --- | --- |
| `plannedAt`、`plannedTrials` | 先固定计划。时间检查不等于可信预注册签名，需团队保留原版本 |
| `comparisonBlock`、`repetition` | S/A 同块、同样本、同重复编号共享基础输入和模型配置；教师顺序另按协议平衡 |
| `source` | 测试材料用 synthetic；真实独立评阅记录才能声明 reviewer-recorded，软件无法验证人类身份 |
| `input` | ZIP 哈希匹配清单；规则、环境、基础证据使用实际导出文件的字节哈希，并在 evidence 中提供对应文件引用。它与内部语义 contentHash 不是同一概念 |
| `phaseMs` | setup、executionWait、reading、editing、publication；合计不超过总耗时。剩余未分类时间仍在 elapsed 内 |
| `runId`、`analysisAttemptId` | R/S/A 完成项有实际 Run；S/A 完成项有实际分析身份；人工组可以不使用系统运行身份 |
| `candidate`、`teacherRevision`、`publication` | 使用 `{path, sha256}` 指向实际快照；完成项必须有后两者，候选本身不构成完成 |
| `model` | H/R 为 null；S/A 记录脱敏配置、实际发送次数、请求/已收到响应、token、币种和计价材料。未知用 null；丢失响应仍计请求，S 不允许多次调用 |
| `rating` | 尚未评阅为 null；否则引用独立评阅材料，并逐项填写误报/漏报/未执行、事实/归因/引用错误、建议可执行性、修订量与再用意愿；未采集项为 null |
| `priorExposure`、`blinded`、`pixelsRead` | 按实际填写；截图索引不等于模型已看像素，已接触样本也不能写成未知以外的未接触 |

材料路径限项目内部，不跟随符号链接，不接受绝对路径、反斜杠、父目录跳转和硬链接；单文件 64MiB、总读取 256MiB。文件 SHA-256 核对能发现字节变化，不能证明原记录真实、独立或已授权。操作者拥有的材料目录不能在校验期间并发替换。

汇总保留各组计划、已记录、缺失、完成、失败、中止、合成/声明评阅、未评分、未知费用和完成项总耗时。已知费用按 CNY/USD 分开列小计，未知项不变成零；不混币种、不丢失败、不自动作收益结论。

本工具不调用模型、不注册真实学生、不发送材料给教师；这些行为和评价结论仍需实际完成。S 的独立运行配置与 A 的受限循环必须分别保留，不能把 A 第一轮重新贴标签为 S。

当前报告页可在同一存档上分别发起 S/A，并关联对照分析，操作和条件见 [模型说明](MODEL_SETUP.md)。存档中的 `baseInputHash` 是规则、基础结果与基础证据清单的规范化来源哈希，不是本账本 `input` 所需的导出文件字节哈希，不能直接代填。配对结果、原始请求/响应、独立评分和发布终点仍需真实收集；配对入口不自动生成已完成的实验账本。

## 下载配对材料并连接账本

教师在报告页展开“查看分析记录”，找到已登记对照关系且结束的记录，点击“下载配对材料”。两端必须是同一 Run 的独立 S/A、相同封存来源与模型配置；取消、降级和中断记录也保留。历史未登记配对关系的记录不会自动拼成实验。

ZIP 包含实际基础/本组补充证据文件、规则、基础结果、测量环境、共用模型配置、各自候选和逐次输入/响应/状态，以及导出时教师版本和最新发布的上下文快照。使用一致性数据库快照，读取文件后再次核验长度和 SHA-256；缺失或损坏时整包拒绝，最多 64 MiB 材料/1000 文件/100 操作。所有权仅限所属教师，响应不缓存；其中包含私有诊断、学生源码片段和模型原文，不能直接公开。

`manifest.json` 列出其他文件的字节数和 SHA-256，不含自身；哈希只能核验字节完整性，不证明来源身份。`evaluation-materials.json` 提供 `common` 和 `arms` 材料映射，明确 `ledgerReady=false`。连接已有预登记账本时：

1. 将整包解压到项目内私有目录，例如 `.data/evaluation-materials/<自选唯一目录>/`。先核对 manifest；不得覆盖其他实验材料。
2. 给映射中的相对路径加上该目录前缀，哈希不变。`input.ruleSha256/environmentSha256/baseEvidenceSha256` 分别取 `common.rule/environment/baseEvidence.sha256`；原 ZIP 哈希取 `originalZipSha256`。这些公共材料和相关证据需要列入 trial.evidence。
3. 两组 `model.configuration` 都引用 `common.modelConfiguration`，各自策略/提示版本见 analysis.json。S/A 模型可见输入不相同，不能宣称控制了提示文本变量。配置未指定温度不等于温度零或供应商版本固定。
4. 根据逐次操作记录核实实际调用。`reserved` 只是预留，不证明请求发出；`unknown` 不能当作成功响应或删除。映射列出全部模型操作及输入/已保存响应，完成计数仅指 completed，不代填正式 `model.calls`。原请求登记哈希覆盖原调用信封，与 request.json 的文件字节哈希含义不同。
5. 继续按真实操作填写预登记计划、教师代号、接触/盲评状态、五段计时、独立评分、每组真实教师修订与发布终点。导出时最新教师版本/发布仅在 context 中，不自动归属于任一组；评分、计时、费用/币种和每组发布保持 null。逐次 actualUsage 保留原始用量，不猜测合计或费用。
6. 使用 `pnpm evaluation:check <账本路径>` 核验完整账本。材料映射本身不是该命令接受的 trial，未完成的人工环节不能通过改字段伪装完成。

原始 ZIP 不在本包中，仍须使用登记样本。只有本组补充证据被收集，context 发布快照可能引用其他历史材料；它不是一份独立可恢复发布备份。本功能不调用模型、不改报告、不自动登记试验。
