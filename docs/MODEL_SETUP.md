# 真实模型接入与验收

## 当前方式：学生和教师自行配置

普通ZIP项目分析已使用每账号独立配置。进入「项目分析」，点击「模型设置 / 配置我的模型」，选择服务商、模型并填写自己的API Key。「保存配置」不调用模型；「测试连接」发送一次短提示，可能产生少量服务商费用。之后上传或重新分析使用项目所属账号的密钥，未配置不回退到平台 `.env`。删除密钥不删除历史报告。

支持官方DeepSeek、OpenAI、通义千问端点，可自填对应模型ID，不接受任意代理地址。真实验证的是DeepSeek Flash，其他选项不等于模型质量已验证。教师与学生独立，服务商向密钥所属账户收费，金额以服务商账单为准。

配置对下一次分析即时生效，无需重启；排队或执行期间锁定配置。高级设置可指定模型实际窗口与单次输出预算，容量留空表示使用应用预算，不保证模型容量。每次保存更换配置版本，每次请求前校验任务冻结的版本。

密钥AES-256-GCM加密保存、不回显。主密钥在被忽略的 `.data/model-credentials.key`，正式环境支持 `MODEL_CREDENTIAL_KEY`（64位十六进制）。和数据库分开备份，恢复须提供匹配主密钥；已有密文时不会自动补建遗失的主密钥。详见[个人模型实现与验证](verification/2026-09-28/PERSONAL-MODEL-SETTINGS.md)。

离线备份验证脚本会将主密钥另存到 `.data/model-key-backups/<备份UUID>/model-credentials.key`，数据库及证据位于 `.data/backups/<备份UUID>`。恢复时二者缺一不可；数据库归档ZIP不包含该密钥，同机两个目录也不等于异地备份。请通过受控渠道分开保管，不加入公开源码包。[真实业务恢复记录](verification/2026-09-29/PERSONAL-MODEL-RECOVERY.md)。

2026-09-29起，课程AI总结与Agent也使用个人密钥。任务页默认「仅基础检查」，可为下一次创建检查明确选择AI总结/Agent，费用归点击创建检查的账号；教师报告页重新分析使用教师自己的配置。源码与课程AI共用配置编辑锁，不能在排队/运行期间更换密钥。保存不会收费；基础检查不需要模型。

下方 `.env` 内容保留为显式服务端诊断、测试工具及历史验收记录，**不再是普通ZIP或生产v2课程分析的计费密钥来源**。`pnpm model:check --request` 等主动诊断脚本仍会使用其明确加载的环境密钥并可能收费。库级合成provider注入仍用于隔离测试，不是运行中个人密钥缺失时的兜底。未保存计费人/密钥版本的旧排队课程AI不会自动切换密钥，基础结果保留，可由教师明确重新发起。

## DeepSeek 官方接口（2026-09-28）

当前已配置官方 `https://api.deepseek.com`、模型 `deepseek-flash`。根据当日[首次调用](https://api-docs.deepseek.com/zh-cn/)、[模型规格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)和[JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode)，使用 `/chat/completions`、非流式 JSON 模式；交互分析显式发送 `thinking: {type: "disabled"}`，不发送其他厂商的 `enable_thinking`。官方默认思考开启；本应用选择关闭以控制等待时长，并将实际开关保存在任务快照。该选择不是思考模式质量对比结论。

```dotenv
MODEL_BASE_URL=https://api.deepseek.com
MODEL_NAME=deepseek-flash
MODEL_API_KEY=replace-locally-only
SOURCE_MODEL_CONTEXT_TOKENS=1000000
SOURCE_MODEL_MAX_OUTPUT_TOKENS=12000
SOURCE_MODEL_TOKENIZER=utf8-conservative
```

API key仅存在本地忽略配置中，不写入前端、源码或验证报告。使用 `pnpm exec tsx scripts/import-model-config.ts <本地私有配置文件>` 合并配置，不覆盖其他业务设置；空闲时加载新服务。`pnpm model:check --request` 会发送一次固定小请求、记录实际用量，不验证项目分析质量。

当日文档同时列出 `deepseek-v4-pro`，适配器支持相同的思考参数；本轮真实测试只使用 Flash，不能声明 Pro 已实测。1M 是文档列出的模型窗口，本应用仍按阶段选取源码并保留更小的输入/阅读/输出预算，不会直接上传整个 ZIP 给模型。

迁移012新增逐次模型调用用量：成功、失败、取消均可查询已经收到的usage；超时/断连和未返回usage保留为未知，不伪造为零、不自动重发付费请求。历史NULL记录明确显示没有账本。只有已知Token小计，没有基于未采集缓存命中和时段信息推算精确价格。

## 普通项目源码分析的容量配置（v4.2）

普通ZIP的100MiB上传、500MiB展开和16MiB保留源码限制是应用资源策略，不是模型上下文容量。源码分析支持以下可选配置，课程总结/Agent原有预算不因这些字段扩大：

```dotenv
SOURCE_MODEL_CONTEXT_TOKENS=
SOURCE_MODEL_MAX_OUTPUT_TOKENS=12000
SOURCE_MODEL_TOKENIZER=utf8-conservative
```

`SOURCE_MODEL_CONTEXT_TOKENS` 空白表示模型窗口未知；显式值须为16384—2000000整数，并根据所用服务/模型文档核实，不能只凭名称推断。应用安全余量为max(2048,窗口×2%向上取整)，输入上限为min(500000,窗口－最大输出－安全余量)；配置后剩余输入小于8192会拒绝启动。窗口未知时输入分配为120000，这仅是应用预算，不保证服务商接收。

`SOURCE_MODEL_MAX_OUTPUT_TOKENS` 为每请求输出上限，1024—32768，默认12000；实际请求取阶段要求与此值的较小值，仍须核对服务商上限。`SOURCE_MODEL_TOKENIZER` 仅支持 `utf8-conservative`、`cl100k_base`、`o200k_base`。后两者只有在明确匹配模型时才选择；不能当作DeepSeek的准确分词器。默认按UTF-8字节保守估算，没有声称是任意模型的严格上界。协议封装/JSON模式开销由余量承担；文本分词数也不等于供应商计费数。

所有源码请求（含修正）在发出前核对完整system/user、输出及安全预算，同时保留768KiB输入字节上限、快速100000/深入180000字符阅读上限和510/810秒时限。目录元数据、入口索引和源码片段分别分配输入预算；读取只保留完整代码行。超过预算报 `MODEL_CONTEXT_BUDGET`，不额外调用模型或伪造报告。

报告“模型容量与实际用量”分别显示配置/估算与服务商usage；全缺失为未知，部分返回为已知小计，不按零计，不在缺少真实价格时估算费用。源码任务从迁移011版本起在上传/重新分析入队时保存不可变的模型配置和容量策略快照，不含密钥；每次模型请求（包括修正）前核对当前配置，变化即以 `SOURCE_CONFIGURATION_CHANGED` 停止，不自动重排或改用其他模型。页面显示本次固定的模型名称。修改配置需空闲时重启服务；旧报告不重写。历史NULL快照明确表示未保存入队条件，旧排队任务仍沿原执行时策略运行，不能视为已有冻结证据。

快照比较涵盖provider、模型名称、接口地址、温度、思考开关与窗口/输出/余量/分词预算；不保存或比较API key，也不能冻结服务商在同一模型别名背后的版本。源码阅读算法变更不包含在模型配置快照内。失败后的部分模型用量已由迁移012持久化，不能把无报告当作零消耗。[冻结与恢复验收](verification/2026-09-28/SOURCE-EXECUTION-SNAPSHOT.md)。

导入模型配置文件时只要求MODEL_BASE_URL/MODEL_NAME/MODEL_API_KEY；若新文件没有上述可选容量字段，会清除旧模型对应的可选值，避免错误继承。无效容量配置在替换.env前拒绝。当前js-tiktoken仅为本地计数依赖，不发送源码。DeepSeek接入采用UTF-8保守估算，不声称已验证其精确分词器。跨模型质量/费用对照仍需独立实验；历史403保留原模型身份。

工程证据见[容量预算验收](verification/2026-09-28/SOURCE-CONTEXT-BUDGET.md)。下方为既有模型接入历史，不能以早期小请求成功否定后续博物馆深入调用的403失败。

2026-09-28 已导入用户提供的本地模型配置，小请求连通成功。同一登记团队样本上的真实总结和 Agent 调用均已生成候选；此前 Agent 超时记录仍保留。详见 [真实调用记录](verification/2026-09-28/T09-live-model-integration.md)。不能从连通或候选生成推断教学质量。

## 配置位置

在项目根目录私有 `.env` 中填写以下三个字段（参照 `.env.example`，保留已有其他设置）：

```dotenv
MODEL_BASE_URL=https://你的兼容服务地址/v1
MODEL_NAME=服务商实际支持的模型名称
MODEL_API_KEY=在本地填写真实密钥
```

地址填写 API 基址，不要附加 `/chat/completions`；适配器会添加该路径。远程地址要求 HTTPS，不允许 URL 内含用户名、密码、查询参数或片段。服务须支持非流式 Chat Completions、`response_format: json_object` 和 `max_tokens`。不能只凭模型名称推断兼容性。

`.env` 已在 `.gitignore` 中；不要把 key 发到聊天、截图、报告或公开仓库。此程序不会读取 Codex/其他项目的凭据来代替本项目配置。Windows 文件权限仍以当前用户的本机安全设置为准，不能把 POSIX mode 当作已验证的 Windows ACL。

## 首次分析模式与可重复参数

在同一私有 `.env` 中可设置：

```dotenv
CODELAB_INITIAL_ANALYSIS_MODE=summary
MODEL_TEMPERATURE=0
```

`CODELAB_INITIAL_ANALYSIS_MODE` 仅接受 `off`、`summary`、`agent`，默认 `agent`。off 生成结构化基础报告、不调用首次模型；summary 运行 `sealed-text-summary-v3-compact-input`，单次调用、无工具、结果未知不自动重试；agent 使用既有有界工具循环。拼写错误拒绝启动，不能悄悄回落成另一个实验组。API 和 worker 应加载一致的配置。

新 Run 入队时把模式写入 `execution_config.initialAnalysisMode`；已排队运行保持原模式，重启或请求重放不改它。旧历史/库级测试运行没有该字段时保留原 worker 回退语义。此开关只影响首次分析；教师显式“重新分析”默认 Agent，也可在报告页选择独立的一次性总结，不受此开关改变。off 不是关闭整个服务模型能力。

改变配置后，在没有活动执行时停止并重启 `pnpm dev:workspace`，随后创建新检查。不能编辑已有运行的数据库字段来重贴实验标签。没有模型配置时，summary/agent 都不会产生真实模型分析，基础报告仍可复核发布。

`MODEL_TEMPERATURE` 可选，有限数字 0—2；空值不发送，实际服务端默认值未知，不能称为已固定。显式值纳入发送请求和持久模型配置；0 不会被误当作未设置。部分服务/模型不支持该字段，需通过真实连通检查确认兼容性，失败不自动降级移除参数。重新分析排队后，当前模型配置包括温度必须与保存值相符，否则拒绝发调用。首次分析模式在入队时固定，模型实际配置则在创建分析尝试时登记，两者不是同一冻结时点。

这个开关提供独立 S 路径，不自动建立公平 S/A 实验。不同 Run 重新执行产生的基础证据不应假定相同；正式配对仍须校验同一封存输入、模型参数、重复安排和教师统一发布终点。现有模式测试使用合成 provider，不能作为真实模型质量证据。

## 同一存档上的 S/A 对照入口

教师打开一份已完成报告，在“分析方式”选择“一次性总结”或“Agent 调查”，点击“重新分析存档”。前一次结束后切换到另一种方式，在“对照已有分析（可选）”选择对应记录，再发起分析。可先 S 后 A，也可先 A 后 S；已有候选按方式和分析身份分别显示，由教师选择是否采用，不自动编辑或发布报告。

一次性总结只使用封存案例文字，最多一次模型调用，无工具、补查或格式重试；独立租约、取消、未知结果不重发与回收行为沿用重新分析队列。Agent 保留受限工具循环。二者都由基础事实生成基础反馈，不把教师修订或另一份模型候选作为基础反馈输入。

配对绑定同一 Run 的已结束独立分析，要求方式相反、基础规则/案例结果/证据清单的规范化 SHA-256 一致，且 provider/model/endpoint/temperature/enableThinking 记录相同。排队保存策略、材料哈希和配对 ID；开始时再核对材料和配置。不匹配报错，不悄悄解除配对。历史记录没有材料哈希时不能直接作为配对来源。

这里保证的是同一封存材料来源，不是两个提示词字节相同：S 收到文字案例和基础反馈，A 的首轮还包含可访问材料索引，后续可读取源码或补查。各自提示版本和实际模型请求都独立存档。后端未宣称两个模型看到完全相同的文本，也不能保证供应商内部模型版本固定。补查带来的额外材料和成本需要计入 A。

失败、中断或取消记录也可关联，以保留实验失败分母；配对关系不表示两边成功或效果优劣。界面保留最近十条分析供选择，完整记录仍在数据库。真实实验仍需预先安排重复/顺序、独立教师评阅和相同质量的发布终点。教师可点击“下载配对材料”，获取原始请求/响应、候选和证据的私有 ZIP；它提供账本材料映射，不自动生成已完成人工评测的账本。

## 两级检查

```powershell
pnpm model:check
# 确认配置后，发送一次固定的小请求：
pnpm model:check --request
```

第一条不联网、不调用模型，仅验证字段及适配器的地址规则。第二条最多发一次请求，15 秒期限，输出 token 上限 64；输入只要求返回 `{"status":"ok"}`，不含学生源码或项目证据。此调用可能计费，不自动重试失败或结果不确定的请求。

公开摘要保存在 `docs/verification/<日期>/model-<id>/result.json`；不含 key、原始响应或服务地址，记录配置/输入/响应哈希、实际 usage 和状态。缺 usage 为 null，缺计价信息的费用为 null，不填 0。完整不含 key 的配置、请求与原始响应保存在忽略目录 `.data/model-verification/<id>/`，按私有材料管理。

直接运行脚本时退出码：0=配置通过或连通性通过，2=缺配置，1=请求/配置/本地审计错误。包管理器可能包装非零退出码，自动化应读取 JSON。`configured_not_contacted` 不表示服务可达；`smoke_passed` 只证明本次固定 JSON 请求成功，不证明真实模型的事实、引用、工具选择或教学质量。

## 本地文件导入与精简反馈协议

用户已准备本地配置文件时，可运行 `pnpm exec tsx scripts/import-model-config.ts <本地路径>`。只导入 MODEL_BASE_URL、MODEL_NAME、MODEL_API_KEY 和可选 MODEL_TEMPERATURE，保留数据库等其他设置；输出只列字段名。未提供温度时清除旧覆盖，不假定服务端默认为 0。禁止把文件内容粘贴进日志、截图或文档。

最新提示版本为 `sealed-text-summary-v4-observation-bounds` / `restricted-text-agent-v4-explicit-support`。模型只返回 criterionId、observation、possibleCause、nextStep、causeSupport、causeEvidenceRefs，服务端从同一封存基础反馈恢复执行步骤、案例与观察证据，强制待教师复核。causeSupport 仅允许 direct、limited、insufficient，表示证据支持程度，不能用 source/manual 替代；提示和一次格式修复均明确该约束。总结保留完整封存案例，基础反馈仅发送上述六字段，要求列表仅包含本次启用条目。S/A 单次输出请求最多 2200 token，尝试总额仍为6000；实际用量照实保存、未知不计零、超总额回复不生成候选。候选仍经过原有证据归属及完整报告验证。旧完整格式保留兼容，不能混合字段绕过校验。精简协议降低重复抄写负担，不提高期限或放宽事实验证，也不保证响应及时或语义正确。历史请求与提示版本保留不变。
