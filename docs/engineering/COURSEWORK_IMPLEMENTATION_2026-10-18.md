# 任务化 AI 分析与版本提交：实施记录

日期：2026-10-18，Asia/Shanghai。对应[产品方案 V1](../product/CodeLab_任务化AI分析与版本提交_落地方案_V1_2026-10-18.md)。

本轮已实现课程作业、独立/连续子任务、个人/团队主体、五种来源、固定提交、自查、教师发布和贡献证据的工程链路。自动化回归通过；真实私有仓库授权、真实模型教学质量及真实师生试点尚未验收，不能据此宣布方案的全部产品验收完成。

## 使用入口

登录 v2 工作台后选择「课程作业」，路径 `/assignments`。教师创建作业和首个子任务，在作业页添加后续任务、邀请团队并指定提交人。创建和修订页面均可设置起始材料、允许来源、必需文件、分析范围及辅助代码政策。创建前可预览与学生实际页面共用的任务说明；可保存私有草稿后发布，预览不写入作业。创建、追加任务和补交窗口的时间输入明确按北京时间解释，不受浏览器所在时区影响。

学生选择子任务，粘贴片段、上传 UTF-8 文件/文件夹或 ZIP，也可填写 Gitee/GitHub 仓库和分支/提交。准备快照后还需明确确认正式提交。连续任务从同一主体的前置成功提交选择固定基线，可下载 ZIP 在自己的 IDE 中继续开发。提交不会自动调用模型，不等待 AI 或教师通过即可开始后续任务。

教师打开默认最新提交队列，查看摘要、固定源码、差异及贡献材料，保存评价草稿并确认发布。更正产生新评价修订；新提交不继承旧评价。列表和详情使用同一汇总，只统计每个主体的最新成功版本；学生只看自己的进度，教师看当前班级汇总，退出班级的个人成果不计入当前汇总但保留历史。列表显示最早待交截止；读取列表不创建个人主体，未接受邀请的团队不暴露进度。

自查与正式报告中的文件行号已接入现有源码阅读器：宽屏并排查看，窄屏弹窗，显示固定快照身份并高亮引用行，可切换完整文件、返回引用及关闭后回到触发按钮。查看旧自查不会选择旧快照或清除新快照的正式提交确认；浏览与待提交版本分开保存。见[源码引用专项记录](../verification/2026-10-18/coursework/SOURCE_READER.md)。

常规启动仍用 `pnpm dev:workspace`（需要既有 Docker Desktop runner 已就绪），本地地址 `http://127.0.0.1:5174/assignments`。账号和开发口令沿用私有 `.data/business-v2/development-credentials.json`，本文不复制口令。

## 本轮采用的默认规则

这些是按方案建议落实的实现选择，不将文档里的建议伪称为用户逐项确认：

- 通用输入仅静态分析；既有受控模板执行路径继续独立使用。
- 每个作业内统一个人或团队模式；单前置任务，允许分叉，拒绝循环和跨作业依赖。
- 团队成员接受邀请后生效；指定提交人正式提交。离队后不能继续读取团队成果，提交时成员及平台身份记录保持不变。
- 新代码默认仅提交主体和授课教师可读；学生个人自查不向队友、教师或其他学生开放。
- 数据库服务端接受时刻严格早于截止才正常接受；补交授权仅对指定任务和主体、指定窗口有效，可撤销。
- 个人自查由学生自己的模型计费；正式候选分析由教师显式发起并用教师模型计费。模型配置不存在、失败或取消不撤回正式提交。
- 仓库读取授权与代码向外部模型发送的授权分开；正式授权绑定固定快照与接收方，发送前重查授权和课程访问权限。
- 页面确认也绑定代码上下文与接收方：准备新快照、切换自查会话或接收方变化时，清除对应确认；新建自查和继续旧会话分别勾选，同一身份的正常轮询不清除。详见[确认边界专项](../verification/2026-10-18/coursework/MODEL_CONSENT.md)。
- 新记录暂不自动删除。课程留存期限未确定时，旧删除工具拒绝处理新任务，防止绕过固定快照与评价约束。

不可变记录包括任务修订、代码快照、正式提交和已发布评价。提交事务冻结任务修订、快照、基线、提交操作人、成员和已核验平台身份；按「任务＋主体」分配版本号；相同幂等键和相同请求返回原回执，改变请求被拒绝。

历史任务继续使用原路由、原 ID、版本和共享状态。`course_legacy_*_projection` 提供只读映射，标注历史迟交和快照不完整，不补造旧 SHA、教师补交授权或模型同意记录。

## 来源与分析边界

文件最多 200 个，单文件 512 KB，保留源码总计 4 MB；网页 ZIP 入口最多 8 MB。目录、生成物、二进制、符号链接、LFS 指针及疑似秘密文件被排除并显示原因。秘密检测是启发式检查，不能保证发现全部秘密。选择文件夹时保留浏览器提供的相对路径；更复杂的目录项目可使用 ZIP。

Git 仅调用服务端构造的官方 HTTPS API，拒绝自定义 URL 和重定向。公开仓库可不配置凭据；私有仓库使用用户保存的令牌，密文使用现有本地 vault，撤销后清空凭据。GitHub 使用 Bearer 头；Gitee 按其 v5 文档使用 `access_token`，完整请求 URL 不写入业务日志或回执。部署时若开启代理访问日志，也必须对该参数脱敏。

导入先解析完整提交 SHA，再只按该 SHA 读取 tree/blob，重试保留原 SHA；超时或历史不可读时失败，不悄悄改读最新分支。按任务范围过滤后才读取 blob，最多 5000 个树项，单响应 6 MB，单请求 20 秒、整个导入 240 秒。中断任务恢复为可重试失败。

教学分析使用一次模型请求的受限静态流水线：优先必需文件和目标范围；源码最多 96 KB，再按本人模型的上下文预算减少低优先级文件。输出记录已读/未读路径和预算；不自动执行代码，不给予终端或任意联网工具。目前没有实现模型自主多轮检索、符号搜索和工具循环。方案列出的工具是建议，本轮采用确定性读取范围；跨文件复杂项目的教学充分性仍需评测。

L1 定位解释、L2 深入提示、L3 主动请求代码按顺序开放。L1 提示要求位置、原因、差距和一个引导问题；L2 解释概念并给一个小步骤及验证方式，避免完整算法。代码层同时要求冻结修订与最新教师政策允许。报告须恰好覆盖任务目标，包含影响说明，明确判断必须有可定位引用，拒绝越界引用和明显虚构运行结论；历史报告缺少影响字段时显示需人工确认，不改写旧记录。系统提示和语法检查无法证明自然语言完整答案、隐蔽提示注入或模型误判已被全部阻止；这些属于真实模型评测范围。

静态运行结论校验另已修复明确否定、询问和条件句误拦截，保留跨子句/字段肯定断言拒绝；失败只保存字段/规则和内容摘要。29 条离线用例及既有 8 份报告回放通过，仍不能作为语义零漏检或真实教学质量通过的证明，见[专项记录](../verification/2026-10-18/coursework/REPORT_POLICY.md)。

另已修复 L3 代码许可的字段范围：仅对应建议字段允许局部代码，摘要、解释、影响、验证和限制仍校验。规则扩展为 35 条，真实队列替身验证建议成功、摘要拒绝且原文不泄漏；L1/L2 防完整解答及 L3 局部代码提示同步增强，但未追加真实模型请求，不能声称已解决旧报告中的语义质量问题。见[字段边界记录](../verification/2026-10-18/coursework/HELP_POLICY.md)。

共享教室 IP 的 GET 读取按服务端验证账号计数，同账号跨会话、路由和 IP 共用每分钟 240 次；公共健康读取仍按 IP 240 次，登录按 IP 10 次。后续完整课堂写循环复现了旧写规则的干扰：50 人第一轮上传/提交成功后，第二轮 50 次上传全部 429。因此写请求也已改为每个经验证账号每分钟 100 次，跨会话/路由/IP 共用，不提高单账号额度，保留认证、CSRF 和登录 IP 防刷。复用已有会话结果，无额外认证查询。50 个构造学生完成两轮文件导入/提交、幂等重放，构造教师人工发布 50 份评价，350 次写入全部成功，V1/V2 源码分别冻结。专项两种数据库各 9/9，工作台已空闲重载且业务表哈希不变，见[写额度专项](../verification/2026-10-18/coursework/WRITE_QUOTA.md)和[原读取范围](../verification/2026-10-18/coursework/READ_QUOTA.md)。这些仍不是生产容量或真实师生试点证明。

贡献材料来自固定基线到当前提交的历史，只有已确认祖先关系并匹配提交时核验平台账号 ID 才归因成员。提交操作人、Git 作者和成员声明分别显示。同名不合并，merge 标注，缺失历史/ZIP/未知身份显示证据不足，不计算贡献百分比、不用行数直接评分。平台账号归因也不能证明代码独立创作。
