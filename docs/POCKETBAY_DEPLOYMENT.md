# PocketBay 独立线上实例

授权范围：新建独立线上实例，保留 AI 项目解读、课程 AI 辅助评阅与人工发布，不迁移本机历史数据、账号或模型密钥，不开放用户代码执行。不是把校园试用模式直接开放公网，也不覆盖本机工作台。

## 新增启动入口

`pnpm start` 调用 `scripts/pocketbay-start.ts`，只加载新生成的 `.env.pocketbay`，不加载原 `.env`。

- 数据库连接仅从平台 `DATABASE_URL` 读取，不允许本机/Compose 地址。
- `PORT` 由平台提供，绑定 `0.0.0.0`；启用 v2 和 Secure Cookie，强制关闭执行。
- 打包时依据授权返回的项目标识，将准确 HTTPS Origin 加入安装包内的 `start` 命令；不改写前端 API 地址，不创建第二个域名。
- 数据目录为平台 `POCKETBAY_DATA_DIR` 下的 `codelab`，密钥加密文件在此生成并保留，不上传原工作台的加密密钥。
- 执行目录、runner 令牌和平台共享模型密钥不用于该实例。
- 启动先运行现有迁移，再在空业务库创建一个独立教师负责人和空试用班级。重复启动只核对，不重置账号或密码；未标记的非空业务库拒绝初始化。

本轮不增加匿名访问或开放自助注册。已有的师生权限和班级隔离仍然生效；首次负责人账号不应作为所有人的共享账号。

## 配置和打包

`scripts/pocketbay-package.ts` 的 `prepareOnlineCredentials()` 只生成云端专用配置：

- `CODELAB_BOOTSTRAP_EMAIL`：`owner@codelab.online`。
- `CODELAB_BOOTSTRAP_PASSWORD`：独立随机密码，仅存 `.env.pocketbay`。该文件被现有 `.gitignore` 忽略，不在公开说明中展示密码。

PocketBay 配对页必须批准该文件后才能打包。其余本机配置、`.data`、历史报告、数据库备份、凭据和已构建目录均不在安装包内。实际归档用源码白名单，仅包含根构建清单及 `apps`、`packages`、`scripts`、`templates` 的必要内容；应用资源随源码保留。生成归档逐项解压核对 SHA-256。

安装包包含新的负责人密码，应作为私密文件保管。归档和清单保存在 `.data/pocketbay/<随机编号>/`，不写入公开 `output`。配对会话或数据库口令不得写入文档、Git、前端或日志。

## 部署顺序

1. 读取 PocketBay 最新机器部署协议和数据库协议。
2. 创建新项目配对会话，只提交配置路径元数据，不提交原连接串。
3. 由用户在网页确认项目、配置、套餐和数据库，不代替用户接受条款或授权。
4. 声明托管 PostgreSQL `migrate=none`，仅新建空库，不导出/上传本机数据。
5. 按授权的配置清单生成源码归档，再串行上传、轮询候选版本。
6. 仅在当前候选部署成功后核对 HTTPS 页面、健康接口、登录、v2 路由、模型配置状态和空库身份。
7. 不擅自回滚、覆盖其他应用，或在运行节点资源不足时反复上传。失败按官方错误类别和实际日志处理，最多三次部署尝试。

本文件不作为部署成功回执；实际项目地址、发布编号、构建失败和验收结果另行记录。

## AI 验证边界

代码层面保留两种 AI 功能。首次上线没有用户个人模型密钥，负责人须登录后自行配置；模型费用由其对应模型账户承担，不使用本机个人密钥回退。

无个人密钥时可以验证页面、权限、上传和人工评阅，以及模型配置入口是否可用，但不能宣称真实 AI 调用已成功。真实调用需要另行获得适当密钥和调用授权，不用替身测试冒充教师减负证据。
