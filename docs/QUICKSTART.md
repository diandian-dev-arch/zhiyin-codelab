# CodeLab 完整操作路线

## 普通项目 ZIP 分析（2026-09-28 新增）

先打开「模型设置」，选择服务商、模型并保存自己的API Key。学生和教师独立配置，未配置不能发起AI分析，不使用平台共享密钥兜底。保存配置不调用模型；「测试连接」和正式分析会使用密钥所属账户的额度。当前支持DeepSeek、OpenAI、通义千问官方端点；仅保存成功不等于连接或分析质量已经验证。

上传前先选“快速概览”或“深入分析”。快速用于认识入口和主要模块；深入增加两轮沿代码线索的调查，等待和调用量更大。详情页展开“调整模式并重新分析”，可在深入模式选择最多6个重点目录，不选则调查全局。运行时选项锁定，轨迹展示真实轮次；停止后不自动重放。目录阅读地图是结构导航，不能当作已证实的依赖图。[模式验收与边界](verification/2026-09-28/SOURCE-ANALYSIS-MODES.md)。

打开 http://127.0.0.1:5174/projects ，登录后直接上传普通源码 ZIP（最大100MiB；页面简写为100MB），无需创建课程或套用Vue模板。上传后自动分析，显示实际文件读取、关键词搜索和复核轨迹；完成后阅读模块、业务链路、问题建议、反证复核与阅读路线，点击引用定位代码。反证复核保留撤回理由，待核实条目不当作已确认漏洞。支持停止、重试与历史记录；离开页面不取消后台任务。此入口只做静态片段分析，不运行项目，也不代替下方实训验收。

普通ZIP展开总量不超过500MiB（含跳过文件），最多20,000项；保留UTF-8源码总计16MiB、单文件512KiB，依赖/产物/敏感配置会跳过。页面的“实际分析范围”分别展示导入、跳过、实际读取文件片段和行数，跳过原因可展开查看。导入量不是模型阅读量，快速/深入分别按100,000/180,000字符阅读预算工作；历史报告不伪造新增统计，同一ZIP重复上传返回原项目，不会重写历史源码或补读先前跳过的文件。课程作业ZIP上限仍为10MiB。[100MiB真实浏览器验证](verification/2026-09-28/SOURCE-IMPORT-100MB.md)。

用户授权的博物馆实际源码包已完成真实模型与反证复核：最终v3.1为481文件索引、19文件片段读取、6次搜索、约53秒。报告给出的建议不是已确认漏洞，模型仍有语义偏差，详见 [交付结果与人工更正](../output/museum-source-analysis/博物馆源码分析结果.md) 与 [最终实测](verification/2026-09-28/source-project-9a5fda4b-89f2-4807-a01a-0ce249a24123/result.json)。

当前交付是 B 版真实工作台，入口为 http://127.0.0.1:5174/。只使用已授权的团队构造样本；`output` 中的 HTML 是历史原型。没有模型配置时，真实检查、教师复核、发布和复提比较仍可使用。

## 启动与登录

原开发机已经配置好环境时，在项目根目录执行：

```powershell
pnpm runner:desktop status
# 若控制器尚未启动：
pnpm runner:desktop up
pnpm dev:workspace:supervised
```

Windows推荐Node24.19.0，工作台拒绝24.0—24.15。`pnpm workspace:runtime`可先核对项目选中的Node；与其他项目共用电脑时可按[项目运行时设置](REPRODUCE.md#工作台运行时选择)单独指定，不必修改系统PATH。旧版或无效配置会明确拒绝启动。

保持工作台终端运行，使用 Ctrl+C 主动停止。守护入口独占回环端口3103；仅对已就绪子进程的异常退出最多重启3次，依次等待2/4/6秒。首次启动失败、正常退出或主动停止不会循环重启。不要同时运行第二个入口；需要调试时仍可使用原来的 `pnpm dev:workspace`，但它没有自动恢复。另一台机器先按 [复现说明](REPRODUCE.md) 安装依赖、构建执行镜像，不直接照抄当前机器的运行配置。

教师账号 `teacher@codelab.local`，学生账号 `student@codelab.local`。在本机 `.data/business-v2/development-credentials.json` 查看生成的口令，不需要发送到聊天。建议教师和学生使用不同浏览器或独立隐私窗口，避免登录会话互相替换。

## 第一次完整走通

| 顺序 | 操作者 | 页面动作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 教师 | 实训任务 → 创建任务，填写名称和说明 | 任务可打开 |
| 2 | 教师 | 选择验收包并发布新规则，核对要求后勾选确认 | 新规则已发布 |
| 3 | 学生 | 打开同一任务，选择 `fixtures/correct.zip` → 保存提交 | 提交已保存，尚未执行 |
| 4 | 学生 | 创建检查 → 查看报告 | 进入队列；发布前只看到等待反馈提示 |
| 5 | 教师 | 打开任务对应报告，等待检查结束 | 五项核心要求的八案例结果及运行证据可查看 |
| 6 | 教师 | 逐项查看截图、日志与反馈；需要时修改并保存 | 教师修订与原始结果分别保留 |
| 7 | 教师 | 逐项确认本条内容，再发布报告 | 发布绑定当前确认过的修订 |
| 8 | 学生 | 刷新本人报告，打开截图和公开证据 | 读取已发布反馈；不能读取教师草稿 |

“确认内容”表示教师已复核反馈，并不把失败或未执行改成通过。人工可读性项需要教师判断，系统不伪造自动结果。任何修改保存后，都要重新确认受影响的内容才能发布。

## 再次提交与定位问题

同一任务和规则下，依次提交 `fixtures/filter-defect.zip`、`fixtures/fixed-with-regression.zip`、`fixtures/correct.zip`，每次保存后都创建新检查。教师比较页应分别反映筛选问题、筛选修复但持久化回归、以及后续修复。每次重新检查全部启用案例，旧发布报告保留。

重新发布规则或改变实测环境后，比较可能显示“不兼容”，此时不能把结果差异直接称为修复或回归。`fixtures/build-error.zip` 用于观察构建错误：相关行为应为“未执行”，不是功能失败。

## AI 候选与重新分析

学生和教师在各自账号的「模型设置」中保存自己的密钥，操作见 [个人模型使用说明](PERSONAL_MODEL_GUIDE.md)。普通项目和课程 AI 都不以平台 `.env` 作为未配置账号的付费兜底。保存配置免费；测试连接与分析由密钥所属服务商账户计费。当前尚未完成独立模型效果验收。

课程任务页默认「仅基础检查」，不调用模型。发起者可为下一次创建检查主动选择 AI 总结或 Agent；创建时固定本次模式、计费账号和配置版本。已有存档的“重新分析”使用教师自己的模型配置，可选择一次性总结或 Agent 调查，不重跑基础检查，也不覆盖教师已经修改的报告。先前分析结束后，可切换另一种方式，在“对照已有分析（可选）”关联前一次记录；材料和模型配置不一致时拒绝配对。候选分别标明方式和身份，需要教师显式采用、复核、确认后才能发布。模型失败时继续使用基础报告。

配对的两次分析结束后，展开“查看分析记录”，点击“下载配对材料”，可保存含实际证据和模型调用记录的 ZIP。取消记录也保留，材料损坏时拒绝下载。包内包含私有内容，请妥善保存；人工评分、计时和每组发布终点仍需真实采集，详细连接方式见 [评测记录](EVALUATION_RECORDS.md#下载配对材料并连接账本)。

## 遇到问题

工作台私有 `.data/business-v2/lifecycle.jsonl` 按启动实例和PID记录 started/ready、停止信号、worker异常结束及退出码；守护入口另写 `supervisor.jsonl`，记录子进程退出与重启。没有exit事件只能表示未观察到正常退出（例如强制终止），不能单凭这一点归因。诊断日志不包含异常原文或配置；不要把整个私有目录公开。[受控恢复实测](verification/2026-09-28/T11-workspace-supervision.md)只证明空闲工作台子进程恢复，不涵盖宿主或守护进程本身退出。真实演示步骤见 [演示脚本](DEMO_SCRIPT.md)，参赛附件状态见 [交付物核对](SUBMISSION_DELIVERABLES.md)。

| 页面情况 | 操作 |
| --- | --- |
| 无法打开 5174 | 查看工作台终端是否仍运行；不要打开历史原型代替 |
| 执行未就绪或排队不动 | 运行 `pnpm runner:desktop status`；若有活动任务或回收阻塞，先查看状态，不强制重建 |
| 容量不足 | 运行 `pnpm storage:check`；保留报告和证据，不执行全局 Docker 清理 |
| 构建失败 | 查看本次构建日志，修改项目后创建新提交 |
| 无法发布 | 检查是否已保存、当前修订是否逐项确认，以及是否出现较新的提交 |
| 学生看不到反馈 | 确认教师已发布、登录的是提交者本人、查看的是正确提交 |
| 模型未配置/分析失败 | 继续人工复核基础报告；按模型说明检查配置 |

备份与归档见 [数据保留说明](DATA_RETENTION.md)。需要核查旧报告依赖的证据是否完整时，运行 `pnpm retention:check --desktop`；此命令只读检查引用与文件，不删除资料。停止工作台不会主动清空持久数据；不要删除 `.data` 或 CodeLab 数据卷来“重新开始”。

## 教师编辑时登录过期

页面出现「登录已过期，当前输入仍在」时，不要刷新。可以先下载当前未保存草稿，再在原页面为当前账号输入密码，点击「重新登录并继续编辑」。登录恢复后需手动点击保存；如果其他窗口已经保存新修订，按冲突提示保留草稿、载入最新内容并逐项合并，不会自动覆盖。

下载的JSON包含未发布的教师反馈、判断、证据选择和更正理由，请妥善保存。当前没有自动导入或崩溃后自动恢复功能，关闭或刷新仍可能丢失页面内存里的修改。
