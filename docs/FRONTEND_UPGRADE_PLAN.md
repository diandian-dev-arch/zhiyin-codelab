# 知因 CodeLab 前端升级方案 · 杏光 Studio 2.0

> 范围：`apps/web`（Vue 3 工作台：登录、实训任务、任务与提交、验收报告、AI 项目分析）。
> 状态：第一阶段（视觉层级 + 交互动效）已在代码中落地，并通过 typecheck、production build 和浏览器验证。

## 1. 现状诊断

| 问题 | 表现 | 影响 |
| --- | --- | --- |
| 层级扁平 | 面板只有 1px 线与 `--shadow`（4% 透明度），卡片、背景、侧栏几乎同一平面 | 用户分不清"可操作卡片"和"说明文字"，首屏重心不明 |
| 完全静态 | 页面切换、数据到达、状态变化都是瞬时替换 | 系统像"跳帧"；检查中、加载中缺乏进行感，用户不确定是否卡住 |
| 反馈薄弱 | 悬停只有背景微变；聚焦只有 outline；按下无回弹 | 鼠标用户缺少"可点"的确认，键盘用户缺少聚焦层次 |
| 数字无语境 | 概览、进度环数字直接出现 | 数值变化（复核数、确认条目）不易被察觉 |
| 品牌氛围弱 | 杏色只出现在少量标签上 | "杏光 Studio"的识别度主要靠 Logo |

## 2. 设计目标与原则

1. **动效解释变化，不装饰静止内容**：只在"到达、响应、进行中、完成"四类时刻出现动画；闲置界面保持安静。
2. **最终状态 = 原有静态设计**：所有入场动画只写 `from` 关键帧；关闭动画（减少动效）时，界面与改造前同样完整。
3. **真实数据**：计数器与进度环只朝 API 返回的值补间，绝不预填或伪造数字。
4. **不碰业务逻辑**：版本路由、复核哈希、保存 / 发布保护、证据 URL 均未修改。
5. **遵守 `DESIGN.md`**：tokens.css 仍是唯一来源；可点击区域 ≥ 44px；焦点 2–3px 动作色；不做营销式落地页。

## 3. Token 扩展（`apps/web/tokens.css`）

只新增，不改名、不改值：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--duration-enter` | 360ms | 元素入场、卡片悬停 |
| `--duration-emphasis` | 560ms | 登录卡片等关键入场 |
| `--duration-data` | 900ms | 进度环 / 数据变化 |
| `--ease-out-expo` | `cubic-bezier(.16,1,.3,1)` | 入场与位移，快起慢收 |
| `--ease-emphasis` | `cubic-bezier(.34,1.32,.64,1)` | 带轻微回弹的强调（指示条、图标） |
| `--stagger` | 45ms | 列表依次入场间隔 |
| `--shadow-raised` | 双层暖色阴影 | 面板、任务集合 |
| `--shadow-floating` | 更深的漂浮阴影 | 悬停卡片、登录卡、拖拽态 |
| `--highlight-inset` | 顶部 1px 内高光 | 主按钮的立体感 |
| `--focus-glow` | 4px 16% 动作色光晕 | 输入框聚焦（在 outline 之外的补充） |
| `--glow-apricot` | 22% 杏色 | 页面背景氛围光 |

既有的 `--duration-press(120ms)` / `--duration-state(160ms)` 继续用于按压与颜色变化。

## 4. 动效规范

| 类别 | 时长 | 缓动 | 属性 | 示例 |
| --- | --- | --- | --- | --- |
| 按压 | 120ms | `--ease-out` | `transform: scale(.975)` | 所有按钮 |
| 状态 | 160ms | `--ease-out` | 颜色、边框、阴影 | 输入框聚焦、导航悬停 |
| 入场 | 360ms，依次延迟 45ms | `--ease-out-expo` | `translate` + `opacity` | 页面区块、任务卡、概览卡 |
| 强调 | 300–560ms | `--ease-emphasis` | `scale` | 当前导航指示条、筛选按钮激活 |
| 数据 | 700–1100ms | easeOutQuart / `--ease-out-expo` | 数字补间、`--progress` | 概览数字、进度环 |
| 循环 | 0.9–2.4s | 线性 / ease-in-out | 脉冲、扫光、旋转 | 仅限"进行中"状态 |

技术约定：

- 入场用独立的 `translate` / `opacity`，悬停用 `transform`，两者互不覆盖。
- 永不在动画之外设置 `opacity: 0`，减少动效时元素直接处于最终态。
- 进度环用 `@property --progress` 注册为 `<percentage>`，让 `conic-gradient` 可插值。
- `<details>` 平滑展开用 `::details-content` + `interpolate-size`，属于渐进增强；不支持的浏览器保持原生开合。

## 5. 逐页改动

### 5.1 全局外壳（`App.vue`、`motion.css`）
- 页面右上角极淡的杏色径向光晕，统一品牌氛围；`::selection` 改为杏色。
- 侧栏当前项：左侧 3px 动作色指示条（`scaleY` 回弹展开）、图标染动作色、`--shadow-raised`。
- 顶栏：滚动超过 8px 后加 `is-scrolled`，变为 80% 透明 + 16px 模糊 + 底部柔和阴影。
- 每次路由切换，`.content` 的直接子元素按顺序上浮淡入（利用现有 `RouterView :key` 的重新挂载）。

### 5.3 任务与提交（`TaskV2.vue`）

### 5.4 验收报告（`ReportV2.vue`）

### 5.5 AI 项目分析（`Projects.vue`、`AgentStudio.vue`）

- 表单字段依次入场；登录按钮悬停时箭头前推；输入框聚焦出现 4px 动作色光晕。

### 5.7 对话框与折叠面板

- 工作区内的 `<details>` 平滑展开 / 收起（排除源码树 `.map-files`，避免大列表重排）。

## 7. 可访问性与减少动效

- `prefers-reduced-motion: reduce` 时：所有 animation / transition 关闭，悬停位移取消，`AnimatedNumber` 直接显示最终值；原有四处全局开关保持不变。
- 焦点：保留原 2–3px 动作色 outline，`--focus-glow` 只作补充，不替代。
- 触屏 / 粗指针设备不启用跟随光；所有循环动画只出现在"进行中"状态，不影响阅读。
- 数字使用 `tabular-nums`，补间过程中宽度不抖动。
