## 一、决策摘要

### 1.1 本次究竟解决什么

现有功能已经具备真实源码引用、三项阅读导航、场景说明、阅读建议、反证记录、费用确认和错误恢复基础。问题集中在三个层面：

1. **页面顺序失衡**：已完成报告之前仍堆叠分析管理信息，项目用途几乎不在桌面首屏。
2. **内容没有完成编辑**：栏目名称友好，但正文经常将业务、函数、事务和缓存细节混成一段，用户还要再次总结。
3. **核查上下文断裂**：源码能打开，却遮住正在核实的判断，跨文件阅读依赖记忆。

因此，改造主线是：**完成态重排 → 内容分层 → 证据连续阅读 → 视觉精修**。

### 1.2 确定采用的方案

- 保留现有路由、三个报告标签及证据能力，不新增一级产品中心。
- 完成态取消大幅深色宣传式头部，以紧凑项目身份和正文构成首屏。
- “读懂项目”先呈现用途，再呈现核心业务和推荐阅读入口。
- 模型、费用、过程、常规排除与历史记录集中到一个“分析详情”面板；历史切换在有多份报告时仍可直接访问。
- 完成态只保留一个“重新解读”入口，点击后进入费用确认面板，绝不点击即付费。
- 一期不改变历史报告内容，只改善呈现、文案标签、布局与证据交互。
- 二期为新报告增加可选结构化阅读字段；旧报告不自动重算、不静默调用模型。
- 将验证动作与修复建议分开；旧 `nextStep` 使用中性标签“后续建议”，不伪装成纯验证步骤。
- 桌面证据按需分栏，窄屏保留全屏查看；两种模式共享同一证据状态。
- 沿用现有墨色、纸色、朱砂强调色，不引入第二套视觉主题。

### 1.3 首期发布应让用户直观看到的变化

| 现在 | 首期完成后 |
| --- | --- |
| 先看长文件名、配置、费用和排除说明 | 打开页面直接读到项目用途 |
| “调整范围”和“确认新的项目解读”同时存在 | 一个次级入口，主动进入后再配置 |
| 技术栈与函数链占据默认阅读层 | 业务说明优先，技术信息按需查看 |
| 多个相近的分析详情入口 | 一个稳定入口，内部按任务分组 |
| 源码覆盖原判断 | 宽屏可同时阅读判断和证据 |
| 有问题但默认页很晚才出现数量 | 标签上明确显示线索数量 |
| 历史字段缺失看起来像质量不好 | 解释缺少何种记录，不推断质量 |

### 1.4 明确不做

不增加通用聊天框、全仓库可编辑图谱、自动质量总分、风险仪表盘、逐节点模型调用或额外的大型摘要卡片墙。不通过隐藏异常、减少费用说明、删除历史报告换取表面简洁。

## 二、现状证据与版本关系

### 2.1 本轮证据

目标页面为用户提供的本地项目页，项目 ID 为 `de8b23bc-bce3-4755-966a-8f863cf61a39`，页面展示 2026-09-30 的历史报告。

| 编号 | 已观察事实 | 设计影响 |
| --- | --- | --- |
| E01 | 约 1810×966 视口，项目用途正文位于 y≈939px | 首屏几乎没有交付阅读价值 |
| E02 | “确认新的项目解读”折叠状态仍高约 93px | 已完成态持续为下一次分析让位 |
| E03 | 顶部、费用行、底部分别出现分析详情入口 | 同一辅助任务多次争夺注意力 |
| E04 | 45 个常规排除文件的说明位于报告之前 | 非异常信息被表现成需要优先处理的提醒 |
| E05 | 业务场景正文直接包含多个函数名、事务和缓存细节 | 业务理解与实现核查未分层 |
| E06 | 部分正文块约 1432px 宽，引用约 11.52px 字号 | 扫读和长路径辨认困难 |
| E07 | 引用弹窗可加载、行高亮、Esc 关闭并返回焦点 | 基础能力应保留，改进重点是上下文连续性 |
| E08 | 当前报告不展示 `EvidenceFlowReader` | 不可把源码中的新能力当作本页已有体验 |

以上尺寸仅代表该视口与报告内容，不作为所有设备的固定现状。手机、读屏、200% 缩放、真实模型生成和所有错误状态未在本轮完整验证。

### 2.2 相对 V1 的继承与修订

| V1 方向 | 当前核查 | V2 处理 |
| --- | --- | --- |
| 三项阅读导航 | 当前已有 | 保留，不重建 |
| 场景与源码证据联动 | 场景组件和弹窗已有 | 升级上下文保持与按需分栏 |
| 报告优先 | 实际首屏仍被管理信息占据 | 增加可测首屏空间契约 |
| 基础解读与高级选项分层 | 已有折叠配置 | 调整出现时机，完成态不前置配置 |
| `reportQuality` 与受限原因 | 共享契约已有 | 直接复用，不重复新增 |
| 可选结构化链路 | 契约、生成开关、展示组件已有 | 不再列为从零开发；核实能力边界，复用有效结构 |
| 费用摘要紧凑展示 | 当前仍独立占一行并带按钮 | 完成态降到详情；未知费用或相关异常保留必要提示 |
| 阅读建议默认三项 | 当前已有 | 明确一个推荐起点，其余后置且完整可达 |

V2 对阅读布局、内容分层和交互的具体决策优先于 V1 中同项建议；费用、安全、历史保留和教学定位延续 V1。实施时更新设计文档，不能删除早期证据或将历史验收记录改写为本轮通过。

### 2.3 额外发现：测试基线存在文案漂移

`tests/e2e-source-flow/source-flow.spec.ts` 仍可见旧名称，如“AI 项目分析”“项目概览”“模块与链路”和旧导入按钮，而现有页面已使用新名称与保存确认流程。此处只证明需要核对，不代表本轮执行过该测试并发现失败。

首个实施工作包必须区分：过时选择器、真实行为回归、环境问题。可以更新名称断言，但不能删除费用确认、请求数量、版本绑定与焦点恢复断言来让测试通过。

## 三、用户目标与范围

### 3.1 默认使用场景

教师或学生在普通室内照明下，使用电脑连续阅读陌生项目，需要尽快理解业务并有选择地打开源码。因此延续浅色阅读面、深色导航与克制强调色；不因“AI 工具”类别增加整页深色与发光效果。

| 用户 | 第一任务 | 需要的下一步 | 不该先承担的负担 |
| --- | --- | --- | --- |
| 首次接触项目的学生 | 说清用途和一个核心业务场景 | 从关键文件开始读 | 理解模型、Token、全部目录和内部复核术语 |
| 教师或熟练评阅者 | 快速找到核心实现和可追问点 | 核查少量高价值证据 | 反复滚动和进出弹窗 |
| 项目作者 | 理解实现取舍及待验证事项 | 修改前先确认条件 | 把所有 AI 线索当已确认缺陷 |

### 3.2 三种阅读深度，不增加三套模式切换

- **快速理解**：用途、核心业务、推荐起点。
- **深入阅读**：场景说明、模块职责、实现细节。
- **证据核查**：判断上下文、源码行段、相关引用与局限。

通过内容位置与逐步展开提供深度，不要求用户先选择“新手模式/专家模式”。

### 3.3 范围优先级

| 范围 | 本轮决策 |
| --- | --- |
| 项目详情已有报告 | 必做，主要收益所在 |
| 完成态与分析配置切换 | 必做，涉及费用边界 |
| 历史/受限/失败/断线 | 必做，确保结构升级不破坏可用性 |
| 源码查看 | 必做，共享证据模型与焦点行为 |
| 课程内嵌 `ProjectSubmissionReview` | 必做兼容检查，避免共享组件引入管理入口 |
| 项目列表、上传 | 沿用已有流程，只修复必要命名与返回路径 |
| 分析引擎与数据契约 | 二期增量升级，不作为一期视觉改善前提 |
| 全平台主题、教学业务 | 不在本方案重构范围 |

## 四、信息架构与功能去向

### 4.1 目标结构

```text
AI 项目解读
├─ 我的项目 / 导入
└─ 项目详情
   ├─ 项目身份栏：名称、报告时间、报告选择、分析详情、更多
   ├─ 必要状态提示：仅异常/运行任务/范围受限
   ├─ 阅读导航
   │  ├─ 读懂项目：用途 → 核心业务 → 推荐起点 → 深入阅读
   │  ├─ 源码与模块：职责 → 文件 → 可选地图
   │  └─ 待核实问题：观察 → 条件 → 验证 → 证据
   ├─ 按需证据阅读区：与当前判断并排或窄屏全屏
   └─ 辅助工作区（同一时刻只开一个）
      ├─ 分析详情：范围 / 费用 / 过程 / 历史
      └─ 重新解读：模型 / 范围 / 预算 / 明确确认
```

### 4.2 全量内容去向

| 现有内容 | 决策 | 默认位置 | 可达方式 |
| --- | --- | --- | --- |
| 项目名称 | 保留，优先可靠展示名 | 顶部紧凑身份栏 | 全名可展开 |
| 文件名时间戳 | 降级 | 项目信息详情 | 原始名称完整保留 |
| 宣传性副标题 | 移除完成态重复展示 | 空状态可保留一句 | 不作为报告正文 |
| 报告时间与模式 | 保留，简化 | 名称下元数据行 | 详情含完整时间 |
| 历史报告切换 | 保留 | 多报告时显示当前记录选择器 | 一次选择切换 |
| 调整范围 + 新解读折叠区 | 合并 | 更多中的“重新解读” | 打开单独确认区 |
| 用量和费用收据 | 保留 | 分析详情的费用分组 | 头部固定入口 |
| 常规排除 | 降级 | 分析详情的范围分组 | 一行总数及列表 |
| 重要/未知原因排除 | 保留突出 | 报告前紧凑警告 | 直达同一详情的范围分组 |
| 静态分析边界 | 合并 | 报告元数据附近一行 | 完整范围在详情 |
| 技术栈 | 保留，后置 | 源码与模块顶部 | 概览可有“技术实现”折叠，不双份展开 |
| 核心业务场景 | 提升 | 默认阅读页主体 | 选择场景，展开实现 |
| 阅读路线 | 保留 | 核心业务后 | 一项主推荐，更多路线展开 |
| 待核实问题 | 保留 | 独立标签，显示数量 | 默认概览最多一条相关入口 |
| 复核与撤回 | 保留 | 问题页底部折叠 | 不计入待核实问题数量 |
| 模块地图 | 保留但默认关闭 | 源码与模块内 | 明确共享依据与调用关系差别 |
| 关联实训推广大块 | 改为低权重文字动作 | 阅读末尾 | 有真实任务上下文再出现具体行动 |
| 工具事件/模型诊断 | 保留 | 分析详情的过程分组 | 普通用户不必展开 |

功能移到二级不等于隐藏到无标识图标。所有入口采用明确中文名称，并保持费用、范围和历史信息可发现。

## 五、页面布局与首屏契约

### 5.1 默认桌面阅读页

```text
我的项目 / 项目解读

东南亚跨境销量统计与补货预测系统          分析详情   更多
9月30日生成 · 快速概览 · 静态源码解读    当前报告 ▾

读懂项目           源码与模块           待核实问题 2
────────────────────────────────────────────────────
帮助海外仓运营人员，把销量与周期数据转成补货建议。
主要输入、输出及适用角色，用一段短文字说明。

核心业务：从销量到补货建议                  切换场景 ▾
导入数据 → 计算建议 → 人工处理 → 留存记录
业务解释；未知环节明确标出。
查看源码依据                 展开实现细节

建议先读：forecast.ts
先理解补货量公式，再看输入字段从哪里来。      阅读源码
────────────────────────────────────────────────────
更多业务场景与阅读建议（按需展开）
```

示意中的短摘要与步骤只适用于有可靠对应数据的新报告。历史报告显示原概览与原场景说明，不能把示例硬编码为通用内容。

### 5.2 证据打开后的宽屏状态

```text
解释区（保留当前位置）                 证据区（按需出现）
─────────────────────────────┬──────────────────────────
当前场景 / 当前问题            │ 正在核实：补货量如何计算
结论、条件和验证动作          │ forecast.ts · L119–154
                              │ 报告与源码版本标识
已选引用高亮                  │ 高亮代码与必要上下文
其他引用                      │ [上一处] [下一处] [完整文件]
                              │ [关闭证据]
```

默认不预留一块空证据栏。打开后依据内容容器实际宽度决定是否分栏，而不是只看浏览器总宽度。

### 5.3 布局尺寸建议

以下是起始规格，最终以真实内容、缩放及中文字体实测调整；不得以满足像素目标为理由剪掉重要信息。

| 项目 | 建议 |
| --- | --- |
| 阅读主容器 | 最大约 1200px，居中；两侧留出 24–40px |
| 桌面普通段落 | 约 38–46 个汉字宽；英文约 65–75ch，混排需实测 |
| 分栏启用门槛 | 可用内容宽度至少约 1040px，解释与证据均能正常阅读 |
| 分栏比例 | 解释约 45%，证据约 55%；两侧最小宽度优先于比例 |
| 紧凑身份区 | 正常名称约 96–144px；不设置裁切长标题的固定高度 |
| 阅读导航 | 44–48px 高，固定三项，不出现第二层平级导航 |
| 一级段落间距 | 24–32px |
| 标题与正文 | 8–12px |
| 行内辅助信息 | 8–16px，依据语义分组 |

### 5.4 首屏可验收目标

- 基准 1440×900、100% 缩放、正常长度报告、无重大警告时：完整用途、核心场景标题与至少一个证据入口无需页面滚动即可看到。
- 同一基准下，项目用途正文起点目标不晚于 y=300px；这是设计目标，需实测，不是当前结果。
- 长项目名、必要警告、系统字体放大时允许下移，不能隐藏异常或压缩字号来强行达标。
- 390×844 下：首屏读到有意义的用途正文；一次常规滑动能到核心场景和证据入口。移动端不承诺所有摘要同时塞进首屏。
- 首屏常驻不出现完整的重新分析配置、长费用收据、工具事件列表及常规排除解释。
- 不在原页面上再增加一层摘要后保留全部重复信息；每新增一个摘要区域都要明确替换哪一块旧内容。

## 六、逐区域设计规格

### 6.1 项目身份栏

**职责：** 告诉用户正在读哪个项目、哪份报告；不承担产品宣传。

- 主标题优先用已有可信项目展示名；只有原文件名时保留其内容，允许换行并弱化已知导入元数据。
- 不用通用正则任意剥离数字后缀：时间戳可能是合法名称的一部分。只有可由导入元数据或用户明确命名区分时才分离；否则显示原名，最多两行后提供“展开完整名称”。
- 原始文件名、完整 ID、导入时间进入详情，不修改原始记录。
- 单报告不展示空的历史选择器；多报告显示当前日期与模式，历史选择需明确“正在查看历史报告”。
- 头部常用辅助操作为“分析详情”；“更多”包含“重新解读”和必要的项目操作，不增加重复的“调整范围”。
- 当前页面是阅读任务，不强求醒目的主按钮。高强调可留给“阅读源码”或场景中的主要下一步。

### 6.2 用途概览

**职责：** 回答“谁用它，解决什么问题，主要输入输出是什么”。

- 新报告采用 40–80 个中文字符的一句话用途，加一段必要解释；这是生成目标而非旧数据截断上限。
- 不将框架清单、权限枚举和全部函数名混入第一句话。
- 旧报告沿用 `overview`；长内容只按显示层折叠，完整文字一键可见，保留限定条件。
- 不能简单取前 80 字作为新结论，也不能在前端正则提取所谓“核心价值”。
- 概览不是可点击大卡片；链接、按钮与普通文字必须有清楚区别。
- 如果证据不足，直接表达“当前已读源码不足以确定项目用途”，随后给出可阅读模块；不拼接技术栈制造确定结论。

### 6.3 核心场景

**职责：** 让读者理解一次业务操作如何完成。

- 默认选择当前报告第一条有效场景，不擅自根据引用数量推断“最核心”。后端若提供明确主场景，再使用该标记。
- 一个场景不显示选择器；两个场景可用清晰紧凑选择器；更多场景仍保留单层选择，不额外铺等大卡片。
- 默认业务层说明输入、处理、结果；实现细节和全部函数名展开后呈现。
- 旧 `flows` 的正文保留，不自动改造成调用步骤。可通过行宽、段落和引用摘要改善阅读，但没有结构化字段时不宣称已完成业务/实现拆层。
- 已有有效 `evidenceFlows` 复用原结构：业务摘要在上，步骤与关系按需展开；`inferred` 关系保持“待核实”文字，不仅靠虚线区分。
- 有分支时保留分支，不能为了简洁强行排成直线。未知环节进入就近说明，不自动连线。
- 切换场景保留其他标签状态；若证据面板属于上一场景，默认关闭并清理选中引用，避免显示旧依据冒充新场景。关闭后焦点留在场景选择器。

### 6.4 推荐阅读起点

**职责：** 给出下一步明确行动，而不是再提供一段重复摘要。

- 保留报告原阅读顺序，第一项标“建议先读”；后两项作为次级路线，完整列表可展开。
- 标题直接指出阅读目标，如“先理解补货量公式”，不要泛用“先看入口”。
- 文件标签显示文件名与必要目录，配一句“读完应理解什么”；没有新字段时沿用原正文，不生成虚构学习目标。
- 原建议带多个引用时全部保留，可显示“查看 3 处依据”，展开后按原顺序访问。
- 若第一项无有效引用，允许阅读文字说明但不出现空的“阅读源码”按钮；不得通过隐藏该项改变原报告意义。
- “读完后尝试”如果只是历史 `nextStep`，改用中性“后续建议”；二期有独立练习字段再精确命名。

### 6.5 源码与模块

**职责：** 支持按职责定位文件，而不是展示所有图形能力。

- 顶部为紧凑技术栈文字组，显示名称与职责；标签数量多时折叠，不横向无限铺开。
- 模块列表使用标题、职责摘要、引用数量；默认仅第一项展开，沿用原生 disclosure 行为。
- 文件树与地图为独立折叠区；地图名称明确“模块与共享源码依据”，不声称真实调用图。
- 模块正文和引用使用同一证据查看器。
- 无模块数据时说明当前阅读范围不足，并提供文件浏览；不画空网络图。
- 首期不增加全文搜索和图谱编辑；现有文件过滤若可复用则保留，不为本次改造引入额外后端索引。

### 6.6 待核实问题

**职责：** 将观察、触发条件与验证动作联系起来，支持审慎判断。

- 标签显示“待核实问题 2”，数量来自最终保留的 `findings`，撤回记录单列。
- 保留现有稳定排序逻辑及其语义；有引用不等于正确，`direct` 不等于漏洞已证实。
- 每项结构：具体标题 → 观察/可能影响 → 发生条件 → 验证动作 → 源码依据 → 确认后的修复建议。
- 默认最多三项，更多可展开；展开收起不重排或改变原数据。
- 严重程度与证据状态分开表达，不能把“中优先级”和“有引用”组合成安全结论。
- 无问题时写“当前已读范围未形成明确问题线索”，不使用绿色“安全通过”。
- 历史条目缺少条件或验证字段时不补造，显示原正文与“后续建议”；只有缺失信息直接影响理解时才展示一条简短说明，避免每条都堆空字段占位。
- 复核、撤回原因及其引用保留在底部折叠区，展开后使用同一证据机制。

### 6.7 源码证据阅读器

**展示契约：** 每次打开都携带项目、报告、引用和上下文，不只携带一个路径。

```ts
// 拟新增的前端展示模型，不是当前后端 API 定义。
type EvidenceSelection = {
  projectId: string;
  analysisId: string;
  owner: { kind: 'scene' | 'module' | 'finding' | 'reading' | 'verification'; key: string };
  contextTitle: string;
  contextText?: string;
  citations: Array<{ path: string; start: number; end: number }>;
  selectedIndex: number;
};
```

| 行为 | 规格 |
| --- | --- |
| 打开引用 | 一次点击加载，展示上下文和目标行，不等待完整文件 |
| 路径显示 | 短路径可读；全路径可展开/复制，不能仅靠 hover |
| 同名文件 | 递增补足父目录直到能区分，不用相同标签指向不同文件 |
| 上一处/下一处 | 仅在当前判断的引用集合内切换，不跨到另一问题 |
| 代码格式 | 显示行号和目标行；折行选项或局部横向滚动，页面不横向溢出 |
| 完整文件 | 用户主动加载，保留原引用定位，允许返回片段 |
| 关闭 | 恢复原滚动位置与触发元素焦点；触发元素消失则回当前区域标题 |
| 快速连点 | 旧响应不得覆盖新选择，使用取消或请求序号保护 |
| 切换报告 | 清空旧代码与选择；新请求绑定新的 analysisId |
| 请求失败 | 证据区域内显示错误与重读，不清空报告 |
| 未授权/不存在 | 不自动尝试另一项目同名文件，不泄漏路径或内容 |
| 断网恢复 | 只重试允许的源码 GET，不触发分析 |

宽屏分栏为非模态命名区域，不能锁住整个页面焦点。窄屏使用原生对话框并管理初始焦点、焦点约束和返回。阅读器数据状态共享，表现模式变化不能重新发起模型调用或丢失当前引用。

直接浏览文件与阅读报告引用必须区分：文件浏览可不带报告判断上下文，但不能将其标成某条报告的已读证据。

### 6.8 分析详情

采用页面内可展开的辅助区域；头部入口打开并定位该区域，关闭后返回原阅读位置和焦点。不为了管理信息永久占据右侧证据空间。

四个分组为：

1. **阅读范围**：已索引与实际读过的文件/行段、常规排除、重要遗漏、源码版本。
2. **模型与费用**：实际历史模型信息、已知费用估算、未知用量、价格依据和服务商账单说明。
3. **分析过程**：阶段、事件、用时、受限原因、必要诊断。
4. **历史记录**：不同分析时间、模式、状态与可读性；选择后回到报告。

规则：费用缺失不是零；完整报告不是全仓库覆盖；重要遗漏不能通过增加调查轮次补回。相关提示使用任务语言，详细错误码进入展开内容。

### 6.9 重新解读确认

- 完成态从“更多 → 重新解读”进入；尚无报告时“开始解读”为主动作。
- 打开后依次展示实际模型账户、范围、预算与费用归属，最后是明确的“确认并开始解读”。
- 默认范围复用当前产品策略，不因界面升级自动从 quick 切 deep。
- 高级选项保留重点目录、版本比较及必要价格配置。
- 模型配置返回后保留用户预算；不得销毁重建费用组件导致默认值覆盖输入。
- 存在活动任务或状态未知时禁用付费开始，解释原因并提供查询恢复。
- 关闭确认不提交；浏览历史、切换标签、展开详情不提交；刷新不重放。
- 复用报告须由既有服务端策略判定；没有命中时明确可能产生新费用，不能前端承诺免费。

### 6.10 提示合并规则

| 信息 | 常态呈现 | 异常呈现 |
| --- | --- | --- |
| 静态分析未运行测试 | 全局一次紧凑说明 | 不重复成多个大警告 |
| 历史质量未记录 | 低权重解释“历史格式未记录完整性状态” | 不替换成“质量差”或“完整” |
| 常规排除 | 详情内计数 | 用户主动查看列表 |
| 重要/未知原因排除 | 不适用 | 首屏紧凑影响说明与范围入口 |
| 可选结构无效 | 正常回退旧场景 | 保留应用产生的受限提示 |
| 无源码引用 | 不显示伪证据按钮 | 在对应判断旁说明依据缺失 |
| 费用未知 | 详情明确说明 | 与当前分析决策相关时就近提示 |

异常优先级高于首屏高度目标。多条同类警告合并原因和入口，但不能将不同后果合并成“有些问题”。

## 七、状态、历史与恢复

### 7.1 不创建替代后端状态机

前端由既有任务状态、报告可读性、`sourceReportQuality`、连接状态和权限组合得到展示状态。不能新增一个布尔“完成”覆盖这些维度。

| 状态组合 | 展示主体 | 可用动作 | 禁止行为 |
| --- | --- | --- | --- |
| 源码已保存、无报告 | 开始解读说明 | 配置、确认、浏览文件 | 自动调用模型 |
| 排队/运行、无旧报告 | 真实阶段和已用时间 | 查看过程、有权限时停止 | 伪造百分比与完成时间 |
| 运行、有旧报告 | 旧报告 + 紧凑运行提示 | 继续读旧报告、查看进度 | 清空旧报告或误认为它是新结果 |
| 成功、完整性为 complete | 报告正文 | 阅读、核查、显式重分析 | 宣称项目运行正确 |
| 可读、limited | 报告 + 影响说明 | 阅读已有内容、查看范围 | 将受限伪装完整成功 |
| 历史、unknown | 原报告 + 历史格式说明 | 阅读与核查 | 自动升级质量标签 |
| 失败、存在旧报告 | 失败摘要 + 旧报告入口 | 查看旧报告、重新确认 | 删除旧结果或自动重试付费 |
| 失败、无可读报告 | 原因、下一步、费用入口 | 修正配置后确认 | 空白页或假报告 |
| 断线、状态未知 | 暂时无法确认提示 | GET 重连、保留已读内容 | 自动 POST 重放 |
| 已停止 | 记录与已有可读历史 | 显式重新确认 | 承诺无消耗或退款 |
| 无权限/不存在 | 中性不可访问页面 | 返回项目列表 | 透露他人项目内容 |

### 7.2 状态优先规则

1. 权限结果决定数据是否可展示，前端按钮隐藏不能替代服务端校验。
2. 正在阅读哪份报告由明确选择决定，活动任务不应偷偷覆盖它。
3. 新结果完成后显示“新报告已生成”，用户选择“查看新报告”后切换，避免阅读中跳页。
4. 页面重新进入时采用既有默认记录策略；若最新记录失败，提供最近可读报告的明确入口。
5. 报告 ID 改变才重置该报告局部阅读状态，轮询对象替换不应反复切回第一个标签或场景。
6. 关闭页面不代表取消任务；只在用户明确停止且有权限时发起取消请求。

### 7.3 阅读位置与导航

一期保持路由不变，标签/场景/展开状态先在当前会话内保留；切换报告按报告 ID 隔离。若需要刷新恢复，可使用不含源码内容的 sessionStorage，并用用户、项目和报告 ID 隔离键；登出时清理。

不为所有展开状态加 URL 参数。将来支持分享阅读定位时只存非敏感选择标识，接收方仍重新鉴权，不能将分享链接当访问授权。

## 八、报告内容与生成升级

### 8.1 两条实施线

| 实施线 | 可以交付 | 不能声称做到 |
| --- | --- | --- |
| A：现有数据、纯展示改善 | 首屏重排、统一行宽、提示降级、引用缩写、上下文证据、历史中性标签 | 自动获得精炼业务摘要、真正拆开历史验证与修复 |
| B：新报告内容契约升级 | 明确用途、场景业务说明、验证步骤、修复建议、来源关联 | 所有历史报告自动具备新内容，或语义必然正确 |

A 可先发布；B 需要契约、生成、反证复核、评测和回滚共同完成，不以修改提示词代替整个闭环。

### 8.2 字段设计：可选的阅读呈现层

推荐新增可选 `readingBrief`，只作用于新生成报告的阅读摘要，不替换现有 `overview/modules/flows/findings/readingPath`。以下为拟议契约草案，实施时统一到共享 schema；不要直接当成当前接口调用。

```ts
type SourceRef = {
  section: 'modules' | 'flows' | 'findings' | 'readingPath';
  index: number; // 指向最终报告数组，不是复核前草稿
};

type ReadingBriefV1 = {
  version: 1;
  purpose: {
    text: string;
    audience?: string;
    input?: string;
    output?: string;
    sourceRefs: SourceRef[];
    citations: SourceCitation[];
  };
  scenes?: Array<{
    sourceRef: { section: 'flows'; index: number };
    businessSummary: string;
    // 业务活动，不隐含函数调用关系；证据不足可以省略。
    activities?: Array<{ text: string; citations: SourceCitation[] }>;
  }>;
  takeaway?: {
    text: string;
    sourceRefs: SourceRef[];
    citations: SourceCitation[];
  };
};

// 对 finding 拟新增可选字段；已有 body、nextStep 保留。
type FindingGuidance = {
  condition?: string;
  verificationSteps?: Array<{
    action: string;
    expectedObservation: string;
  }>;
  remediation?: string;
};
```

新增展示字段不是事实来源。事实仍需关联最终有效章节与已读源码；不能将一个看似合法的 `sourceRef` 当成语义证明。

### 8.3 建议约束

| 字段 | 内容目标 | 建议硬上限 |
| --- | --- | --- |
| purpose.text | 40–80 中文字符，先业务价值 | 240 字符 |
| audience/input/output | 有据才填，各一句 | 每项 160 字符 |
| businessSummary | 先解释业务，再补必要实现 | 500 字符 |
| scenes | 与已有场景对应 | 最多 5 项，不超现有有效场景数 |
| activities | 有顺序依据才提供 | 0–6 项，每项 120 字符 |
| takeaway | 最多一个有价值重点，可缺省 | 240 字符 |
| sourceRefs | 必须存在且对应最终报告 | 每字段最多 6 项 |
| condition | 具体触发条件或明确未知 | 500 字符 |
| verificationSteps | 动作和预期观察成对 | 1–3 项，各字段 300 字符 |
| remediation | 只给确认后处理建议 | 600 字符 |

这些数值是初始预算建议，须根据 quick/deep 输出 Token 预算验证。不能把每个字段都填满视为高质量，也不能为凑数量编造业务活动、问题或证据。

### 8.4 历史与异常降级

| 数据情况 | 呈现行为 |
| --- | --- |
| 完全没有 readingBrief | 原概览 + 原场景 + 原引用，使用新版布局 |
| purpose 合法，其余缺失 | 使用用途短摘要，其余用旧字段 |
| 可选结构解析失败 | 丢弃该结构，旧报告仍可读；应用记录降级原因 |
| sourceRef 指向不存在项 | 不猜测标题匹配；移除相关增强字段 |
| 引用超出已读范围 | 不发布对应增强结论，按现有引用规则处理 |
| 新旧内容相互矛盾 | 以保守回退为先，移除增强摘要并进入质量评测问题记录 |
| verificationSteps 缺失 | 不将 nextStep 自动归类为验证，显示“后续建议” |
| 复核撤回某问题 | 删除所有指向该问题的摘要关联，不保留醒目的旧风险句 |

“可选增强回退”与“核心报告非法”必须区分：不能把最终核心引用错误一并吞掉，假装只有摘要不完整。

### 8.5 生成与复核改造点

当前 `source-agent.ts` 已包含业务导读、首次术语解释、字数和引用约束，但 `nextStep` 示例仍将“最小修改路径和验证方法”合并。应统一初稿、格式修复、反证复核、最终校验的要求。

推荐流程：

1. 复用现有合成请求生成原报告及可选阅读字段，不新增逐段或逐节点模型请求。
2. 本地验证结构、长度、来源引用和已读范围；格式合规不等于语义正确。
3. 反证复核同时保留/修订可选字段和问题指导，禁止遗漏新字段导致被 schema 静默剥离。
4. 最终章节集合确定后核对 `sourceRefs`。如果现有索引修正流程能可靠提供映射，则重映射；无法证明对应关系时丢弃受影响摘要，不做标题相似度猜测。
5. `findings` 数组缩减、撤回与重新排序前后必须使用显式映射；前端排序不改变报告原数组。
6. 最终产物持久化后经过 API 读取，确认新增字段及应用生成的质量状态没有被剥离。
7. 模型生成的警告不能冒充系统质量状态。`analysisWarnings/reportQuality/reportLimitReasons` 继续由应用判定。

初期建议让 takeaway 优先关联稳定的业务/模块说明；涉及 findings 时必须完成撤回映射测试。若无法在既有调用预算内可靠完成，则先不开放该类摘要，不能偷加一次收费调用。

### 8.6 案例改写规范

**用途示例：** 帮助东南亚海外仓运营人员，根据销量与生产运输周期形成补货建议，并记录人工处理结果。

**场景示例：** 管理员上传 Excel；系统检查格式与数据规则，将有效数据保存为新批次，并刷新后续预测所需数据。

**实现层：** 展开后再显示对应解析函数、事务边界、缓存失效和引用。上述示例不能被实现人员直接塞进所有报告。

**问题示例：** 标题应准确描述已观察条件，例如“特定环境配置下可能使用默认会话密钥”；验证先检查部署环境与密钥加载行为，修复建议另列。实际标题仍须依据源码与复核结果，不能因为本方案给了示例就替换用户历史结论。

### 8.7 内容质量评测

准备至少 12 个脱敏/公开样本，覆盖小型前端、带 API 的项目、脚本、单仓多包、无 README、长名称、多语言、少量证据、重要文件遗漏、无问题、受限与历史格式。样本集不是上线统计结论。

每份从以下维度按 0–2 评分：用途准确、业务可理解、条件完整、证据关联、验证可操作、无重复填充。总分 12，建议准入为单份不低于 9，且下列硬错误为 0：引用不存在、把推断写为已验证、撤回问题仍出现在重点摘要、验证建议直接改变系统却未说明、无依据补造调用关系。

至少由一名能核对源码的人与一名目标读者分别评阅；模型自评不能代替人工。记录新字段增加的 Token、总费用、时延与失败率。真实模型样本运行需在实施阶段确定模型与预算；本次文档交付不执行收费评测。

## 九、视觉、响应式与无障碍

### 9.1 视觉决策

- 采用克制色彩策略：现有纸色表面、深墨正文，朱砂色仅用于当前选中、主要动作与必要状态。
- 参考锚点是现有 CodeLab 设计体系、文档式连续阅读和代码评审中的上下文证据分栏；借鉴职责，不复制外观或增加新风格。
- 完成态不使用大块深色 hero；侧栏已有深色品牌承载，正文无需重复。
- 主体以无框分区、标题和留白组织，边框服务于交互、证据和错误区域。
- 页面不再每节都放英文小帽子、序号和装饰图标；真实步骤才编号。
- 纸纹可保留在外围，但正文与代码区的有效对比度必须按实际合成背景测量。若影响阅读，局部使用实色遮盖，不擅自全局去除所有页面纹理。

### 9.2 字体建议

| 用途 | 桌面 | 窄屏 | 规则 |
| --- | --- | --- | --- |
| 项目名称 | 26–28px | 22–24px | 允许换行，避免展示字体压过正文 |
| 用途关键句 | 20–22px | 18–20px | 常规易读字体、适度加粗 |
| 章节标题 | 18–20px | 18px | 与内容价值对应 |
| 正文 | 16px | 16px | 行高约 1.7–1.85 |
| 辅助文字 | 13–14px | 14px | 不承载关键判断或费用承诺 |
| 路径/行号 | 13–14px | 13–14px | 可复制、可展开、局部换行 |
| 源码 | 13–14px | 13–14px | 等宽，允许局部横向滚动 |

实现时用 rem 与现有 token，像素仅为 16px 基准下的目标参考。不要通过减小文字实现首屏指标。

### 9.3 响应式行为

| 可用空间 | 行为 |
| --- | --- |
| 宽桌面且正文可用宽度≥约1040px | 证据打开后分栏，未打开时居中阅读 |
| 平板或可用宽度不足 | 单栏阅读，证据用大面积对话框并保留判断摘要 |
| ≤760px | 标题操作重排、场景选择器纵向、三Tab紧凑排列 |
| 320px 或放大字体 | 标签可在自身内部换行，不强制横向滚动；完整名称可展开 |

切换响应式表现不应丢失当前源码、引入重复 DOM 标识或让隐藏控件仍在 Tab 顺序中。代码区横向滚动与整页横向溢出必须区分。

### 9.4 可访问性与交互细节

- 保留现有 tablist/tab/tabpanel、roving tabindex、左右键与 Home/End。
- 主要触控目标至少 44×44 CSS px；小图标可用透明内边距扩展触控区。
- 正文对比度目标至少 4.5:1，大字与重要非文本控件按适用标准测量，不根据 token 名称推断达标。
- focus-visible 清楚可见；页面 sticky 区不能遮住焦点目标。
- 页内标签切换保留合适滚动位置；通过“查看问题”跳转时将焦点移动到问题区域或对应标签。
- 非模态证据区不锁焦点；模态证据区正确约束焦点并支持 Esc、关闭按钮与返回。
- 源码加载状态局部播报，不把每条轮询事件写入 aria-live 打断阅读。
- 展开、切换使用约 150–200ms 的必要反馈；移除 padding/width 驱动的悬停位移动画，不让点击目标漂移。
- reduced-motion 下直接切换；默认正文可见，不依赖 reveal 类出现才渲染。
- 200% 缩放检验布局，另用键盘和至少一次真实读屏检查关键路径。

### 10.3 前后端事件契约

一期可保持现有 `citation` 事件兼容，新增可选上下文信息或新增 `evidence` 事件；先迁移两个主要消费者，再移除旧通路。直接文件浏览保留独立 `file` 语义。

每个引用请求继续携带当前 `analysisId`，并由服务端核查该报告属于当前项目及当前用户可访问范围。课程内共享报告与个人报告使用各自现有授权路径，不能为了统一组件而共用越权接口。

### 10.4 缓存和竞态

- 源码缓存键至少包括用户会话、项目 ID、报告 ID、路径与请求范围；不得仅按文件名缓存。
- 完整文件与片段可共用缓存前先确认来源版本与权限相同。
- 切换项目/报告、登出或权限变化时清空相关缓存；关闭面板后迟到响应不得重开面板。
- 快速切换 A/B 引用时保证最后一次选择获胜。
- 不为所有引用预加载完整源码；用户打开后再取，避免页面轻量化却增加传输量。

### 10.5 CSS 层叠治理

当前存在 `style.css → tokens.css → studio.css → motion.css → manuscript.css` 及组件样式。先核对真实 import 次序和 computed styles，再决定覆盖位置。

优先在项目阅读根作用域内建立有限变量和布局规则；避免全局改 `h1/h2/button` 影响登录、任务和课程报告。若为解决纸纹需要增加页面作用域，也应明确生效边界并回归其他页面。删除遗留 `.reader-takeaway` 等规则前先全仓检索真实使用，不凭单个模板判断全局无用。

### 10.6 功能开关

现有开关继续有效：`SOURCE_EVIDENCE_FLOWS=1` 控制生成，`VITE_EVIDENCE_FLOWS=0` 控制前端展示，两者互不替代。

为二期建议新增独立开关（名称为提案，当前不可使用）：

- `SOURCE_READING_BRIEF=1`：新分析尝试生成可选阅读字段，默认关闭。
- `VITE_READING_BRIEF=0`：前端回退使用旧字段，需重新构建。

一期布局可通过可回退构建交付，不必为了每个视觉细节再加一个开关。关掉展示不能删除新数据，也不能改变费用回执。关掉生成不代表旧报告里的增强字段消失。

## 十二、验证与验收

### 12.1 验证层次

1. **静态/单元**：类型、适配、排序、状态和来源校验。
2. **隔离集成**：真实 API/数据库路径上的报告持久化、权限与版本绑定，使用隔离数据。
3. **浏览器交互**：真实点击入口、标签、引用、关闭、历史、确认与断线恢复。
4. **视觉人工**：首屏重点、长文本、响应式、缩放与对比度。
5. **模型质量**：独立样本与人工证据核查，不由 mock 代替。
6. **用户试读**：让实际读者完成任务，不只问“好不好看”。

### 12.2 测试样本矩阵

| 样本 | 必须验证 |
| --- | --- |
| 当前历史报告 | 缺新字段仍完整阅读、原引用保持 |

| unknown | 历史格式解释，不误判质量 |

| 无效 readingBrief | 回退旧内容、不新增模型调用 |
| 无效 evidenceFlows | 原场景可读、受限提示不丢 |

| R14 | 双击确认且模拟回执丢失 | 沿用防重机制，未知状态只查询，不自动重发收费请求 |
| R15 | 无取消权限 | 界面不给误导动作，服务端仍拒绝越权取消 |
| R16 | 后台新报告完成但用户在读旧报告 | 只提示可切换，不抢滚动与焦点 |
| R17 | 无效摘要/缺新字段 | 旧正文与引用保留，不出现空卡片 |
| R18 | 复核撤回重点问题 | 正文、数量、摘要引用一致，无遗留已撤回风险 |
| R19 | 课程内打开相同报告组件 | 证据可用，没有个人费用和重分析入口泄漏 |
| R20 | 禁用新增展示/生成开关并回滚构建 | 旧阅读可用，历史数据不删除、不重算 |

### 12.5 新增测试应关注行为

- 适配器：可选字段缺失/损坏不破坏旧报告；不伪造数据；来源引用存在且未撤回。
- 证据：请求竞态、关闭后响应、报告切换、权限与缓存隔离。
- 状态：新报告完成不抢当前阅读；断线不创建任务。
- 费用：配置返回保留预算，确认外的操作零付费请求。

不为每个间距写测试，不用快照锁死整个模板结构，不把“组件渲染了三个div”作为核心验收。

### 12.6 用户试读与指标

建议邀请至少 5 位目标读者，包含学生与熟练教师/开发者，分别完成：

1. 30秒内说出项目服务对象与用途。
2. 60秒内找到一个核心场景及相关源码。
3. 解释一条问题为何仍待核实，以及下一步如何验证。

记录正确率、完成时间、误点、求助和原话，不只记录满意度。首轮目标为至少4/5完成前两项且不把待核实问题当成已确认漏洞；小样本只能指导迭代，不能宣称统计显著提升。

无需为本轮默认引入线上埋点。若后续增加，先明确事件、存储与隐私边界，只记录必要计数和状态，不记录源码正文、密钥、完整路径或用户输入内容。

## 十三、发布、回滚与风险

### 13.1 发布顺序

1. 保存基线与可回退构建，核对真实前后端版本和数据源。
2. 先发布兼容旧数据的 A 线；在当前历史报告与课程内报告上人工验收。
3. B 线契约和消费端先具备回退能力，生成端默认关闭。
4. 使用公开/隔离样本完成离线与预算明确的真实模型评测。
5. 小范围开启新生成，观察受限率、费用、时延与用户理解情况；既有报告不回填。
6. 记录正式开放范围，更新 DESIGN 和实施验收记录，不只更新方案状态。

运行中的付费任务不能因视觉发布被随意中断；部署前核对活动任务与现有运维流程。文档中的发布顺序不是本次已获得的部署指令。

### 13.2 回滚原则

- A线问题：回退前端构建，保留数据和现有API行为。
- B线内容问题：关闭拟新增生成开关，前端隐藏增强字段或回退旧呈现；已有报告原数据保留。
- 仅关闭展示不会停止生成；仅关闭生成不会删除历史新字段。
- 不删除报告、不重置数据库、不自动重跑模型、不把视图关闭当任务取消。
- 回滚后验证旧报告、同版源码、历史恢复、费用确认和权限，不能只看首页加载。

### 13.3 风险与处置

| 风险 | 预防 | 失败时处理 |
| --- | --- | --- |
| 精简时隐藏重要限制 | 原因分级、受限状态用例 | 恢复显著提示，优先可信度 |
| 摘要与最终复核结果不一致 | 最终索引核对、撤回映射 | 丢弃相关摘要，保留原报告 |
| 源码跨项目/报告串读 | API校验、完整缓存键、切换清理 | 清空错误状态并拒绝回退猜测 |
| 多组件迁移丢失费用防护 | 沿用动作入口与后端策略 | 暂停新确认界面上线 |
| 全局CSS影响其他页面 | 阅读作用域覆盖、真实computed styles | 回退局部样式，避免全局叠加补丁 |
| 旧报告长文本依旧不够精炼 | 明确一期边界、完整可读 | 不用截断/正则生成伪摘要 |
| 新字段增加输出与费用 | 字段预算、复用既有请求、成本评测 | 暂停生成增强，旧流程保留 |
| 旧测试误报或断言被削弱 | 先校准基线、保留行为断言 | 分别修选择器与真实缺陷 |
| 方案再次只停在原则 | 工作包、首屏指标、完成定义 | 未满足不得标整体完成 |

## 十四、完成定义与后续边界

### 14.1 A线可发布条件

- [ ] 正常完成态首屏直接交付项目用途与场景入口。
- [ ] 重新分析为一个明确入口，打开与关闭不调用模型。
- [ ] 常规管理信息降级，重要遗漏和受限影响仍可见。
- [ ] 所有历史文字、引用、复核记录与阅读建议仍可达。
- [ ] 源码查看保留判断上下文；同版、权限、竞态与焦点通过验证。
- [ ] 三标签、场景、历史与运行任务互不抢状态。
- [ ] 课程内嵌报告没有管理入口或数据权限回归。
- [ ] 桌面、窄屏、键盘与200%缩放验收有记录。
- [ ] 核心单元、集成和浏览器回归通过，已有失败已明确区分。
- [ ] 真实项目从列表进入到源码返回的路径已核验。

### 14.2 B线可开放条件

- [ ] 可选字段从生成、复核、校验、持久化到读取全程保留或明确回退。
- [ ] 新摘要没有不成立的来源引用、撤回残留或伪调用关系。
- [ ] 验证动作与修复建议独立，新旧格式标签准确。
- [ ] 没有新增隐式模型调用，实际Token/费用变化已记录。
- [ ] 内容样本评测达到门槛，未达标类别保持关闭。
- [ ] 生成与展示独立回滚演练完成，旧报告不重算。

### 14.3 当前已定与实施时核实

已定：阅读优先、三标签保留、墨纸品牌延续、费用确认不削弱、旧报告不自动重算、先A后B。

实施时需核实而非阻塞文档交付：目标运行实例与部署方式、当前测试失败基线、来源索引映射的具体实现、真实模型评测预算、参与试读人员。实现开始前按工作包解决，不要为这些未知提前制造已完成结论。

### 14.4 不应再次发生的结果

- 新增摘要但原配置、费用、提醒仍全部在首屏。
- 为了显得简洁，隐藏所有受限和费用未知信息。
- 把函数名排成箭头就叫核心业务链。
- 把旧 `nextStep` 改个标签就宣称验证/修复已拆分。
- 以构建成功、mock通过或单次模型成功代替完整验收。
- 为改善历史报告偷偷重算，或把新增内容成本算作免费。
