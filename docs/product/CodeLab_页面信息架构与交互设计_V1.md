# 知因 CodeLab：页面信息架构与交互设计 V1

日期：2026-09-30。对应[教学闭环与低成本项目分析升级方案](CodeLab_教学闭环与低成本项目分析升级方案_V1.md)。本文件是下一阶段设计规格；配套交互原型使用示例数据，不连接正式业务或模型。

用户确认的设计方向：简洁、美观、高级，保留现有设计风格与语言，允许在此基础上充分升级。核心要求是用户能够快速理解整个项目，各功能之间有连续的操作路径。

## 1. 先解决信息顺序，再精修视觉

本轮查看了真实学生项目分析页。报告完成后，页面前部仍依次呈现大标题、个人模型配置、深入调查说明、完成状态、费用和分析范围，再出现较长轨迹及项目正文。用户要先看很多分析过程，才找到项目到底做什么。

本轮实际页面在 898×851 的窗口中，“项目全景”标题位于文档纵向约 1847px，也就是距离顶部约 2.2 个屏幕高度。这是当前单个项目、当前窗口的观察值，不是所有项目的平均结果；足以作为本次信息顺序调整的具体依据。

当前问题主要是：

- 过程信息的面积和视觉权重超过分析结论；运行中的进度块在完成后没有变成简洁状态。
- 项目名称混入上传时间等识别信息，长标题占据首屏；技术栈与项目用途挤在长段文字里。
- 模块、业务链路、问题、阅读路线缺少明确的先后关系，用户需要自己拼出项目全貌。
- 代码证据、费用、覆盖与限制都有价值，但同时铺开后降低了阅读效率。

升级验收应围绕“陌生用户是否能快速回答项目用途、入口和核心链路”，不以卡片数量、动效或报告长度作为完成依据。

## 2. 延续的视觉语言

以当前 [apps/web/DESIGN.md](../../apps/web/DESIGN.md) 和已部署工作台为依据，保留杏色与纸面体系，不沿用历史纸张折角原型中的装饰动效。

| 设计项 | 保留与升级规则 |
| --- | --- |
| 色彩 | 背景 `#F2F2EF`、侧栏 `#E8E9E4`、纸白 `#FFFFFF`、正文 `#24272C`、杏色 `#F3B58B`、主操作 `#A54524`；继续使用现有 tokens |
| 版式 | 左侧稳定导航，主区清楚标题与内容；用留白、细分隔和小标题组织信息 |
| 字体 | 中文系统无衬线；标题克制加重；文件名、代码和版本使用等宽字体 |
| 层级 | 页面标题约 28–32px，章节 18–22px，正文 15–16px，辅助说明 12–13px；响应式调整 |
| 间距 | 8px 基础节奏，内容区 24–32px，段落与控件保持可读距离 |
| 容器 | 数据列表用行，比较用表，独立工具和示例作品用有限卡片；避免一段话一个框 |
| 圆角与阴影 | 沿用当前柔和圆角；浮层有必要层次，正文不靠重阴影分块 |
| 操作 | 每个区域一个清楚主动作；次要动作使用低权重按钮或文本链接 |
| 状态 | 绿色仅表示已完成或已有依据，琥珀表示待核查，红色表示失败；颜色配文字 |
| 动效 | 短过渡服务状态切换，不持续漂浮、闪烁或播放与任务无关的动画 |

专业感来自准确内容、稳定布局和细节一致性。界面可以有识别度，但不采用大面积宣传文案、装饰图表和无法解释的数字。

## 3. 全局信息架构

```text
工作台
  教师：待评、待处理、快速发布
  学生：待交、待互评、待修改、新反馈
实训任务
  任务详情 → 提交版本 → 评阅工作台 → 本轮精选
我的项目
  上传与导入 → 项目概览 → 具体模块、证据与学习路线
学习案例
  班级精选 → 案例导读 → 参考到新任务 / 记录学习点
用户菜单
  账号、模型与额度、偏好
```

项目分析是“我的项目”的详情，评阅工作台是“实训任务”的子流程，不再各增加一组平行导航。页面顶部用面包屑说明来源；同一项目从任务进入时，保留“返回本次作业”的上下文。

原型中可提供师生视角切换以便评审设计。正式产品的角色来自登录权限，不能通过装饰性的角色切换器改变权限。

## 4. AI 项目分析页：阅读优先

主要用户：第一次接触该项目的学生、教师或独立学习者。主要任务：迅速建立整体认识，再有目的地深入。

### 4.1 完成态首屏

```text
我的项目 / 项目分析                         上传新版   分析详情

任务管理看板                         已完成 · 静态分析 · 当前版本
管理待办事项的创建、状态切换与筛选，并在刷新后保留数据。
Vue 3   TypeScript   本地持久化                 查看完整项目信息

概览    模块与链路    问题与证据    学习路线
────────────────────────────────────────────────────────────
项目如何运转                              从这里开始读
输入任务 → 更新状态 → 视图展示              1. 入口与界面
                  ↘ 保存与恢复             2. 状态与事件
                                          3. 数据保存
核心模块
界面与交互     状态管理     数据存储
一句职责       一句职责     一句职责
对应文件       对应文件     对应文件

本次理解范围：已覆盖……；尚未验证……          展开范围与限制
```

示意内容属于教学样例。真实页面必须由对应版本的可信报告生成，不硬编码项目结构或“已覆盖”结论。

首屏遵循以下规则：

1. 标题使用清楚的项目名称；原始 ZIP 名、上传时间和完整标识进项目信息。长名称允许两行并可展开，不把关键区全部挤下首屏。
2. 用两三句话说清用户、问题和主要输入输出。技术栈只保留主要标签，其余展开。
3. 优先展示一条核心业务链和三到五个主要模块，不试图把所有文件画在一张图上。
4. 首屏保留“静态分析”和简短的覆盖限制，不把不确定性全部藏起来。
5. 模型设置不占整块首屏；已完成报告的费用和调查轨迹进入“分析详情”。

“几秒能知道项目做什么、半分钟能找到入口”作为理解测试的设计目标，不宣称已达到。

### 4.2 四个内容页签

| 页签 | 只解决什么问题 | 默认内容 | 下一步 |
| --- | --- | --- | --- |
| 概览 | 整个项目是什么、如何工作 | 用途、角色、输入输出、主链路、主要模块、建议起点 | 点模块或阅读入口 |
| 模块与链路 | 各部分怎样协作 | 模块职责、真实入口、输入输出、调用关系、核心流程选择 | 打开相关代码或切换业务流程 |
| 问题与证据 | 哪些判断值得核查 | 按影响与判断状态组织的问题、引用、反证或撤回说明 | 查看证据、记录判断、加入改进 |
| 学习路线 | 应按什么顺序读懂 | 3–5 步阅读路线、每步理解目标、文件引用与小问题 | 阅读源码并记录理解 |

页签使用单选语义并支持键盘，不把章节选择做成含义不清的多选框。浏览器后退或刷新可恢复当前章节和版本。

模块图必须区分真实可追溯调用关系和仅依据目录推测的组织结构。缺少关系证据时，宁可展示职责列表和文件入口，也不绘制貌似准确的复杂依赖图。

### 4.3 源码证据侧栏

点击文件引用后，桌面右侧打开有明确标题的证据栏，正文仍在当前位置。展示文件路径、准确源码版本、行号、相关片段、对应结论和“返回阅读”。

移动端改为全屏对话框。支持 Escape、明确关闭按钮、焦点返回；代码独立横向滚动，整个页面不横向溢出。打不开引用时显示失败与重试，不用空白区域冒充无代码。

同伴在此处写评价时自动绑定证据位置。教师意见和私人分析轨迹不因为复用侧栏而向同伴开放。

### 4.4 分析详情

统一容纳报告版本、模式与模型、实际阅读范围、跳过文件、费用及未知预留、调查轨迹和完整限制。默认先给简短摘要，长轨迹按阶段折叠，支持必要筛选。

“重新分析”放在这里并明确本次目的、预算与费用承担方；“阅读更多”或“切换页签”不能暗中调用模型。历史报告和重新分析按钮不混在正文小节中。

### 4.5 运行中与异常状态

| 状态 | 主区域如何呈现 | 用户可做什么 |
| --- | --- | --- |
| 初次无项目 | 一处上传入口与支持说明；可打开明确标识的示例 | 上传 ZIP 或关联已有项目 |
| 文件已保存、未分析 | 已识别结构与“尚未生成 AI 导读” | 先提交作业，或确认额度后分析 |
| 排队中 | 真实排队状态；没有可靠队列信息时不伪造名次 | 离开页面、查看已保存内容 |
| 分析进行中 | 当前真实阶段与已用时、可展开轨迹 | 停止后续调用；查看已有历史报告 |
| 已完成 | 默认进入概览；过程块收起 | 看模块、核对证据、学习 |
| 失败或额度不足 | 材料已保存；原因与可执行下一步 | 查看旧报告、调整已明确的配置后主动重试 |
| 结果不完整 | 缺失范围及其影响；只发布已校验的内容类型 | 选择进一步调查；不把草稿伪装成完成 |
| 权限不足 | 不展示私有内容与不存在的操作 | 返回有权限的任务或项目 |

可以提前展示确定性的文件结构，但尚未通过最终校验的 AI 文稿不能冒充正式报告。用户停止后保留实际已用费用和状态，不承诺已发送的请求一定免费取消。

## 5. 通用上传与项目列表

默认上传区域用“上传项目源码”表达目的，直接说明可用于 Vue、React、Java、Python 等工程，无需统一模板。支持说明与当前真实能力同步，不用已禁用的按钮宣称已经支持仓库导入。

上传前只需要选择文件；系统完成识别后提供项目名称、根目录、主要语言、保留与跳过摘要。只有识别不确定或多子项目时才要求用户选择，不让普通小项目也走复杂向导。

课程来源自动带入任务，不再重复选择班级。个人来源默认私有，可以稍后关联作业。分析目的默认“读懂项目”；额外的技术栈参数、关注目录和模型配置折叠在高级设置。

操作明确区分“保存项目”“提交本次作业”“生成导读”，可以在已授权策略下顺序完成，但不能让按钮文案隐藏付费调用。上传进度来自真实字节或真实阶段，没有可靠进度时显示状态而非虚假百分比。

项目列表采用清楚的记录行：名称、语言、来源任务、最近版本、分析状态与更新时间。主动作随状态变化为继续阅读、开始分析或处理失败；费用明细不挤进每条记录。

## 6. 任务发布与任务详情

发布面板只突出名称、要求、班级与截止时间，默认开放项目。量表用简短预览直接确认；互评和修改阶段的默认安排可见且易改；模板执行、附件和详细配置进更多设置。

首次课程分析的授权随 P0-B 一起交付：发布面板及任务设置提供默认关闭的“为本班生成项目导读”。开启后就地显示费用承担者、已选模型配置、每份预算、任务总预算和适用提交版本，教师确认后才生效；没有有效配置时可以先保存设置，不触发分析。关闭后不再为后续提交自动发起分析，已经发生的费用和已有报告保留；正在进行的调用单独按取消规则处理。

学生提交页相应显示“由教师授权生成导读”或“仅提交，暂不分析”。学生可以无个人 Key 完成提交；这项 P0 的教师授权入口不依赖 P1 的平台体验额度，也不能用创建任务动作代替付费同意。

任务详情页首先说明目标、当前阶段和主要动作，再呈现提交或班级进度。教师侧突出待评，学生侧突出自己的下一步，不能对两种角色展示完全相同的仪表盘。

任务列表以状态行取代大面积重复介绍卡：任务名、班级、截止时间、当前阶段、真实待办数量和进入按钮。统计针对全量还是已加载记录必须明确，不能因换了视觉就改变口径。

## 7. 教师评阅与学生互评

桌面评阅工作台采用“作品列表—当前证据与导读—反馈”布局。在中等宽度将列表收成选择器，移动端按作品、证据、反馈依次排列，避免三个窄栏挤在一起。

教师阅读区域围绕任务标准展开；每项显示已有依据与待核查处。反馈区保留一句评语、必要判断、推荐与明确发布动作。AI 候选需要看得到来源，正式确认与采用候选不能混为同一个按钮。

学生互评使用更轻的界面：项目导读、证据、一处优点、一条建议、可选推荐。评价之前不显示其他人票数；避免把教师评分表原样复制给学生。

未保存草稿、保存失败、并发更新和发布结果未知应就地显示并保留输入，不能用短暂的成功 toast 掩盖不确定状态。原型的示例反馈只能说“已更新本地演示”，不模拟真实提交成功。

## 8. 学习案例

精选页突出作品名称、来自哪次任务、为什么值得读、知识点和阅读入口。卡片适用于少量精选，但不做点赞数占主导的热榜。

案例详情以“要学什么 → 核心实现 → 按路线阅读 → 我能如何应用”组织。保留作者和版本、教师推荐理由、同伴贡献及限制；教师可以添加为下次任务参考。

先让用户读懂案例，再按需打开完整项目。案例不自动暴露作者成绩、未发布反馈、私人历史和全部源码。

## 9. 前端与 AI 内容同时升级

视觉重排不能让本身错误的分析变准确。前端依赖以下清楚的报告契约：项目摘要、主要角色、输入输出、模块职责、核心链路、证据引用、判断状态、阅读路线和分析限制分别结构化保存。

前端不通过裁短文字或删掉不确定措辞制造“准确摘要”。如果现有报告无法可靠拆出相应结构，就显示原有可验证内容并标注缺失；新分析按版本化契约逐步升级，旧报告继续可读。

本次内容更新应覆盖跨章节一致性。例如补读了某文件后，“未读范围”需要同步；撤回某问题后，概览不能仍把该问题当确定缺陷；不同版本的引用不能混用。

## 10. 实施切片与验收

先做 AI 完成态的信息重排与源码侧栏，保留原始报告字段和权限；同时完成通用上传页面及任务表单。待开放提交和共读接口就绪，接通评阅、推荐与案例，不用样例界面冒充后端能力。

建议拆分成清晰的界面职责：项目页头、概览、业务流程、模块导航、证据侧栏、分析详情、任务发布、评阅面板和案例导读。沿用 Vue、现有图标和样式 tokens，不为本轮引入新的前端框架。

验收至少包括：

- 桌面 1440px、窄桌面约 900px、手机 390px 的阅读顺序、长标题、换行和无整体横向溢出。
- 主操作触达、页签语义、键盘焦点、对话框关闭与焦点返回、减少动态效果偏好。
- 初次空白、分析中、失败、无额度、无权限、旧报告与缺失字段等状态。
- 教师和学生各走一次发布／提交／共读／反馈／修订／案例流程，真实接口与模型替身的验证分开记录。
- 让初次接触项目的用户回答用途、入口、模块与核心链路，记录找答案的时间与错误，不只询问页面是否漂亮。

## 11. 配套交互原型

[打开原型源码](../../design-proposals/codelab-learning-loop-v1.html)。原型用于比较信息层级、查看师生流程与响应式布局；示例数据不代表真实班级、模型结果或产品统计。

原型覆盖项目概览、模块与链路、问题与证据、学习路线、任务与轻量发布、评阅和精选案例。所有写入仅在本地演示状态中体现，不发送作业、不发布评价、不调用模型。

### 11.1 本轮实际验证记录

验证日期：2026-09-30。使用浏览器读取实际 CSS 视口尺寸，并通过页面操作验证原型；没有调用正式业务接口。

| 验证范围 | 实际结果 |
| --- | --- |
