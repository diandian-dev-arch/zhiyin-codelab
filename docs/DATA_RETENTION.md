## 保留规则

| 数据 | 当前处理 | 原因 |
| --- | --- | --- |
| 提交源码、基础事实、证据、教师修订、发布版本 | 原位保留，不按年龄删除 | 历史报告读取和复提比较依赖这些对象；删除单个文件会破坏引用 |
| 分析候选、模型原始请求/响应、检查点 | 私有保留，不进入公开源码包 | 包含内部诊断和可能的提交内容；不能当作学生公开证据 |
| 已验证备份 | 原备份保留，可生成私有归档副本 | 打包前重新核验数据库 dump 与完整证据清单 |
| 失败备份与失败验证材料 | 保留供排查，拒绝标记为已验证归档 | 文件存在不代表能够恢复 |
| 执行临时容器/网络 | 由既有带身份的回收器按任务生命周期回收 | 不按名称前缀批量删除，不触碰其他项目 |
| 普通源码上传临时ZIP | 正常请求结束即删除；进程强制退出后，由源码上传回收器检查归属并清理 | 仅处理本机、本工作区新版临时命名空间；操作系统确认原PID不存在、目录仅有upload.zip且无链接时才删除。此文件是请求接收缓冲，不是数据库中的源码、报告或证据 |

当前默认不设置到期删除。真实课程接入前由课程负责人确认保留期限、学生权利和删除范围；已实现下述数据库引用检查和持久保留记录，异地恢复验证与可审计删除仍待完成。不能以磁盘告警触发旧报告删除，也不能把“已打包”解释为原件可删除。

源码上传回收在API就绪时及每60秒执行，使用主机/工作区摘要和创建者PID识别临时目录。进程存活、PID可能复用、权限不足、未知系统错误、额外文件或符号/硬链接均不强制回收；旧版无归属的临时目录保持原样。计数是每轮观察值，多实例并发不能相加当作唯一删除量。它适用于本机同一PID命名空间，不应让不同容器的PID命名空间共享该临时目录，也不是防御同账号恶意替换目录的沙箱。回收失败只记固定诊断，不触碰历史资料；磁盘准入仍独立生效。详见[上传残留回收验收](verification/2026-09-28/SOURCE-SPOOL-RECOVERY.md)。

## 登记和解除专项保留

运行迁移 008 后，本机运维可为某个 v2 Run 登记额外保留原因，例如正在独立评测、问题调查或备份核对。保留范围包括该运行的提交关联、封存事实、历史报告、分析/私有调用和证据；检查报告会把该运行的已登记证据标记为 `retention_hold:<ID>`。

```powershell
# 用实际 Run ID 替换占位符；请求 ID 首次生成后保存，重发必须沿用。
$retentionRequestId = [guid]::NewGuid().ToString()
pnpm retention:hold --desktop hold <Run-ID> $retentionRequestId "正在进行独立评测"

# 使用上一步返回的 eventId 作为 Hold-ID；解除也需要新的请求 ID 和原因。
$releaseRequestId = [guid]::NewGuid().ToString()
pnpm retention:hold --desktop release <Hold-ID> $releaseRequestId "独立评测已完成归档"
pnpm retention:check --desktop
```

这是本地运维入口，凭工作台私有数据库配置访问，不提供学生或匿名 HTTP 入口；记录 `access_method=local_operator`，不伪造已核实的个人身份。原因 3—300 字，属于私有运维资料，避免填入密钥和不必要的个人信息。终端只输出动作、事件 ID、是否重放和 `deletionAuthorized=false`；完整原因可从私有检查结果 `holds` 查看。

同一请求 ID 与相同内容重发返回原事件，不重复追加；改动动作、对象或原因会拒绝。两个独立连接并发登记同一请求，只产生一条；同一保留记录最多有一条解除记录。保留和解除均追加保存，数据库触发器拒绝 UPDATE、DELETE 和 TRUNCATE；解除后仍能追查原原因与时间。历史业务资料不会因登记或解除被修改。

当前默认 `retain_all` 生效：解除专项保留不是删除授权，也不释放磁盘空间。该机制是应用数据库内的持久保留依据，不是抵抗数据库超级用户或宿主文件手工删除的 WORM 存储。课程Run尚无历史删除命令；普通ZIP项目现有下面的逐项目授权流程，两者不可混用。

## 普通ZIP项目的专项保留与授权清理（迁移014）

本地运维入口 `pnpm retention:source` 不开放学生/教师HTTP删除接口，不按时间或磁盘压力自动执行。普通项目与课程Run是不同对象；此流程仅处理 `source_projects`、对应全部 `source_analyses` 与 `source_model_calls`。不影响课程提交/发布报告、个人模型密钥、备份或外部副本，不代表数据已经从供应商或备份中擦除。

先核对准确的项目及所有者UUID，生成只含身份、计数、阻塞原因和内容指纹的预览：

```powershell
pnpm retention:source --desktop plan <Project-ID> <Owner-ID>
```

预览保持 `deletionAuthorized=false`，不复制项目名称、源码或模型报告。指纹覆盖项目、全部分析、调用回执、保留历史；执行时重新读取并核对，任何变化要求重新预览。排队/运行分析、尚处于started的模型回执、活动专项保留或异常源码集合均阻止清理。历史unknown回执是已结束但结果不明的记录，与started不同。

保留/解除均通过私有JSON请求文件传入，不在命令行展开理由：

```json
{
  "projectId": "<Project-ID>",
  "ownerId": "<Owner-ID>",
  "requestId": "<首次生成并保留的UUID>",
  "action": "hold",
  "reason": "正在进行独立评测"
}
```

```powershell
pnpm retention:source --desktop hold <private-request.json>
# 解除文件改为 action=release，加入返回的 holdId，并使用新的 requestId
pnpm retention:source --desktop release <private-release-request.json>
```

实际删除必须另行制作确认文件，授权引用应指向负责人确认的真实记录，不能把“预览通过”填写为授权。课程政策仍由负责人确定；外部评测引用不能自动穷尽，操作者须实际核对后才声明已核对。

```json
{
  "projectId": "<Project-ID>",
  "ownerId": "<Owner-ID>",
  "requestId": "<首次生成并保留的UUID>",
  "fingerprint": "<最新预览返回的64位指纹>",
  "reason": "<明确的清理原因>",
  "authorizationReference": "<真实授权记录的私有编号>",
  "externalReferencesReviewed": true,
  "confirm": "DELETE_SOURCE_PROJECT_AND_ALL_ANALYSES"
}
```

```powershell
pnpm retention:source --desktop delete <private-delete-request.json>
```

这是不可撤销的当前数据库删除，应用不提供撤销按钮；只能按既有备份恢复流程恢复备份时点数据。使用同一事务保留锁、目标行锁和不可变审计表；删除与回执同时提交，任何失败全部回滚。原请求重发返回同一回执，修改请求内容会冲突。回执保留最小身份、计数、指纹、理由和授权引用，不保留被删除源码/报告。它记录的是 `local_operator` 的授权声明，不证明声明人真实身份或法律有效性。数据库超级用户仍可破坏该边界。

迁移未加载会明确拒绝，命令不自动迁移。请求文件上限16KiB；锁等待5秒、单SQL30秒，单项目历史读取上限64MiB、10000分析/160000调用/10000保留事件，超过拒绝，不截断后删除。备份和外部副本的保留/清理须另行授权处理。

课程清理前可先核对同一学生、同一任务的全部历史，而不是选中单个Run：

```powershell
pnpm retention:course-plan --desktop <Task-ID> <Student-ID>
```

此命令仅生成影响范围清单，结果保存在私有 `.data/course-retention-plans/<UUID>/result.json`。统计该组合的全部提交（包括无Run提交）、运行、执行、分析/操作/私有IO/检查点、教师修订/发布、事件和保留历史。使用只读一致性事务，拒绝超过10000提交或Run，不加载源码、模型正文或私有检查点内容；单SQL预算30秒。

活动工作或未完成回收、reserved/sent操作、专项保留、隔离材料、跨范围retry/模型配对引用、旧版历史均明确列出。复提比较动态选择此前提交，因此预览不能缩小为某次Run，也不会自动把其他学生/任务纳入清理。

预览始终 `deletionAuthorized=false`、`deletionExecutorAvailable=false`，并明确课程政策、外部引用人工核对、课程删除执行器尚未完成。它不锁定未来提交/教师修改，不验证文件完整性或全部JSON语义，不是删除令牌；下面的证据完整性审计仍是另一项检查。课程记录的不可变触发器没有被关闭或绕过。[实现与实测](verification/2026-09-29/COURSE-RETENTION-PREFLIGHT.md)。

后续内部组件：[维护事务与指纹](verification/2026-09-29/COURSE-RETENTION-TRANSACTION.md)已在隔离数据库验证。它在课程全局空闲时取得表写锁、重新检查活动工作、读取目标全部内容并核对指纹；普通读取可继续，课程写入及用户/任务修改暂时等待。组件未接入线上入口，也未授予删除权；不能将只读预览命令误认为已经启用该维护事务。

```powershell
pnpm retention:check --desktop
```

命令只用于当前 CodeLab Docker Desktop 工作台。先核对数据库容器归属标签、运行状态和本机绑定，从私有配置读取连接凭据；不会启动/重建容器、运行迁移或更改报告。以 REPEATABLE READ / READ ONLY 事务读取运行、执行清单、补充清单、教师历史修订、分析候选/配对关系、发布快照及隔离事件，并统计私有调用/检查点。

检查会建立“证据文件 → 哪些执行/操作/历史修订/发布/分析正在保留它”的清单，核验清单/发布快照哈希和实际文件长度/内容哈希；缺失引用、损坏文件、异常路径或符号/硬链接均明确报告，不跟随链接扫描。所有 Run 及以前提交默认保留，因为前次提交比较通过历史记录动态选取，不能只查看最新报告。

结果保存在新的 `.data/retention-audits/<UUID>/result.json`，包含引用身份和文件路径，属于私有运维记录；终端仅打印计数、结果路径和文件哈希。退出码 0 表示已检查范围无问题；2 表示发现问题或文件遍历不完整；1 表示数据库、身份校验或命令执行失败。单类数据库记录最多 10000 条，最多遍历 20000 个目录项、深度 6、核验 512 MiB 引用内容，达到边界不会声称完整。

`unreferenced_retained` 仅表示数据库快照中未找到引用，可能仍由在途执行、隔离材料、外部评测或人工调查使用。所有结果固定 `policy=retain_all`、`deletionAuthorized=false`。隔离材料保留并提示人工排查；未封存内容不因此升级为可信事实。检查不读取私有模型原文/检查点内容，不验证全部报告业务语义；数据库快照与文件扫描不是原子快照，活动记录数量会附在结果中。检查显示专项保留/解除历史和活动计数，但自身不取得长期保留锁、不生成删除计划，也不提供绕过不可变触发器的入口。

## 归档已验证的离线备份

先按 [备份恢复步骤](verification/2026-09-28/T12-backup-recovery.md) 完成离线备份和独立恢复验证。随后日常工作台可运行，归档命令只读取已有备份，不连接或更改在线数据库：

```powershell
pnpm backup:archive <backup-uuid> <verification-date>
# 已存在备份示例
pnpm backup:archive 1117a243-b13a-49d7-9fbd-912fea546031 2026-09-28
```

命令核验恢复记录 passed、sourceUnchanged、cleanup，逐字节哈希核对 dump 和证据，拒绝损坏、缺失、多余证据以及链接。生成 ZIP 后解压内存内容逐项验证，写盘后再次核对 ZIP 哈希。归档包含 database.dump、manifest.json、evidence-v2、恢复记录和新增 ARCHIVE_MANIFEST.json，不重复打包恢复演练产生的第二份证据目录。

含013个人模型配置的备份还需核对 `.data/model-key-backups/<backup-uuid>/model-credentials.key`：配置数量、恢复成功数量、32字节主密钥和原备份指纹必须一致；缺失、被替换、链接或元数据不完整会拒绝归档。主密钥不放进ZIP，归档清单v2及操作结果明确记录 `modelVault.status=separate_key_verified`、`keyIncluded=false` 和单独存放位置。转存时将主密钥通过独立受控渠道保存，并在目标机器核对指纹；重新生成一个主密钥无法解密旧配置。历史未记录个人密钥状态的旧包标记 `not_recorded`，不伪造“不需要密钥”。

产物存入 `.data/backup-archives/<操作UUID>/backup.zip`，摘要在同目录 result.json。每次生成新目录，不覆盖原包；输入最多 64MiB、10000 条遍历预算、32 层目录，超过时拒绝，不产生可用归档声明。此工具面向操作者拥有且不被并发修改的备份目录，不是抵御恶意目录替换的文件系统隔离边界。

归档**没有加密**，包含账号哈希、源码与私有证据，不应上传公共仓库、放入公开 output 或发到聊天。当前副本和原件同盘，只改善可转存性，不提供异地容灾，也不释放空间。转存到受控独立存储后，需比较单独传递的 SHA-256，并在目标环境完成恢复演练；哈希不能证明发送者身份。
